# 工作区读取、编辑与恢复契约

## 读取契约

| 操作 | 返回与读取范围 |
| --- | --- |
| `workspace.summary` | 项目摘要、封面素材、项目默认字幕样式、模型、Skill、系统信息及刷新版本；不展开镜头集合、资料正文、主张集合、运行或日志。 |
| `project.get` | 当前项目、项目／公共素材、最新运行摘要。带上已知 `revision` 和 `assetsVersion` 后，未变化的 `project`／`assets` 字段省略；切换项目时不复用其他项目的条件。 |
| `run.list` | 按创建顺序倒序读取运行摘要，包含已完成步骤 ID，不读取活动结果或执行事件。项目、状态和创建时间可组合过滤，先过滤再按稳定游标分页。 |
| `run.events` | 指定运行的最新一页事件，使用事件序号继续向前读取。界面展开详情后才请求。 |
| `run.activities` | 指定运行的分页活动元数据；结果仍通过 `node.result` 显式读取。 |
| `asset.list` | 分页素材及索引查询的使用状态，可按类型过滤。本页角色参考图一次批量查询，归档角色仍保留占用；目标项目的镜头在打开应用对话框后读取。 |
| `shot.candidates` | 按项目与镜头在 SQLite 内过滤已成功候选，使用 `offset`／`limit` 分页，返回总数及本镜头未完成运行摘要。默认 20、最多 100 条，界面每页 8 条；不加入工作区摘要。 |
| `shot.candidate.get` | 显式读取候选并验证运行、镜头归属与媒体哈希；缺失或损坏素材不能应用。 |
| `project.readiness`／`project.readiness.cancel` | 按已保存项目及可选执行范围检查模型角色、参数、角色参考、本地媒体和引擎条件；以项目和请求 ID 取消。返回错误、提醒及对应修复入口，不提交制作任务。 |
| `asset.recovery.start`／`get`／`scan`／`confirm`／`cancel` | 创建缺失素材检查、分页读取清单、扫描指定目录、确认匹配候选或取消任务。清单含当前和冻结引用；分页按任务 generation 隔离重新扫描。 |
| `character.list`／`character.get` | 角色按创建游标分页，默认 20、最多 100 条；角色详情和最多四张图片的元数据按需读取，不传图片字节。 |
| `cost.list`／`cost.summary` | 费用按稳定创建游标分页，默认 20、最多 100 条，可按项目／运行筛选；汇总在 SQLite 按币种聚合，不把账目加入后台摘要。 |
| `cost.tasks` | 按制作任务在 SQLite 汇总全部费用，再按任务第一条费用的稳定游标倒序分页；默认 20、最多 100 个任务，可按项目筛选。同一任务的新费用不移动分页边界，不把同一任务拆成几页汇总。 |
| `cost.task.get` | 按运行 ID 返回任务完整汇总、状态、修订和冻结的项目／流程／步骤／镜头名称；不返回模型配置、提示词、产物或密钥。详情费用通过 `cost.list` 按需分页。 |
| `audio.mix.prepare`／`audio.mix.get` | 按完整项目草稿准备真实混音，返回可轮询任务；结果含内容键、文件哈希、实际镜头顺序／时长及响度分析，不直接保存项目。 |
| `audio.mix.levels` | 按混音键读取最多 60 秒的真实 100 Hz 双声道峰值／RMS 窗口，不从波形推算电平。 |
| `audio.silence` | 对已保存修订的目标源音频做实际静音检测，返回参数、音频 ID／哈希和候选区间，不自动删除。 |

分页接口最多返回 100 条；运行、事件和素材默认 100 条，角色与费用默认 20 条。运行、事件、素材、角色和费用使用 `before` 游标和 `nextCursor`；镜头候选使用 offset，素材恢复清单使用 offset 和 generation。新增记录不会移动后续游标。展开的历史刷新第一页，已加载的较早页面不重复读取；素材集合变化时重新读取素材第一页。候选面板每次新生成完成或显式刷新后重读第一页。

制作记录的 `createdAfter` 包含起点，`createdBefore` 不包含终点；两者使用带秒的 UTC `Z` 时间，允许一至三位小数，拒绝更高精度、无效日期和空／倒置区间。界面的开始、结束日期按当前系统本地日历解释，结束日期包含当天，转换为下一本地日期的起点；夏令时日期不按固定 24 小时累加。切换筛选会隔离上一查询的分页和迟到结果；正在编辑的无效日期范围显示错误并暂时隐藏结果，不提交无效查询。清除筛选恢复全部记录。

工作区数据库当前使用 Schema 11，升级前创建快照并在事务失败时回滚。轻量项目摘要和素材引用索引由 SQLite 触发器与源项目写入同一事务维护，包含背景音乐、参考音频、字幕来源、剪辑 Source／Plan 和恢复所需原素材；摘要包含默认字幕样式与实际首帧，并遵守视频制作中的字幕开关。文档能力标识保护关键帧、固定子流程、并发和视频制作设置。普通摘要读取不展开完整项目、资料或主张集合，素材版本由素材写入更新；升级不改写原运行快照或检查点。

`workspace.snapshot` 是完整诊断与原生验收接口，会展开执行历史；普通界面使用轻量摘要、条件详情和分页接口。

### 制作前检查

制作前检查只读取已保存项目，不保存当前编辑、不读取系统密钥、不创建运行、活动或费用，也不联系供应商。它复用执行时的模型校验和本地媒体预检，对所需现有文件核对大小与完整 SHA-256。报告包含保存修订、检查范围和时间；未保存内容单独提示。后台工作区更新只标记结果过期，用户显式重新检查才再次读取和校验文件。

所选有效脚本、画面或配音步骤可能生成新的上游输入，相应缺失内容显示为提醒，实际执行仍会再次校验。Agent 的只读输出不当作新分镜，锁定镜头的既有缺失素材也不降级为可由生成修复的提醒。固定子流程按依赖顺序检查，不改写其持久化版本或节点顺序。供应商连通性、实际计费及最终编码结果仍由各自的真实验收证明。

检查可关闭取消，过期或迟到结果不能覆盖另一个项目或执行范围的报告。修复入口定位步骤、模型连接、项目素材恢复、角色、现有制作或运行环境建议；未知业务提交不会因检查、取消或重新连接而自动重提。

### 批量素材恢复

素材库的“恢复缺失素材”默认检查当前项目，也可检查整个工作区，包括历史制作、批量导出、步骤产物与回收站的引用。选择目录后先按大小筛选，再校验完整 SHA-256；文件名相同不作为匹配依据。每条显示最多八个相同内容候选，用户确认具体来源，单次最多恢复 2000 项。扫描可取消，失败后可重新扫描继续；清单跨页选择，重新扫描后旧 generation 的页和选择不能混入新结果。

恢复将原始字节写回原受管理位置，保留素材 ID、路径、版本、项目修订和冻结快照。原位置已有不同内容、元数据冲突、符号链接、路径越界或权限不足时保留现有内容并解释原因，不通过重绑新 ID 或改写历史来绕过问题。同一物理文件的共享引用合并恢复，发布前再次核对来源、记录及完整内容；失败回滚仅删除仍属于本次操作且内容未改变的文件。

任务持久记录扫描、暂存和修复状态，重启后中断任务不伪装成功。实时进度从内存读取，阶段变化、取消、失败及文件归属／发布边界持久化完整清单，避免随扫描项数反复写入整份清单。无法证明归属的崩溃暂存文件保留并提示，新尝试使用独立暂存名继续。文件恢复后通过独立的可用性通知重试图片、视频、缩略图、波形、时长及失败的本地混音；不增加素材内容版本，也不重提远端生成任务，已就绪的混音保持可用。

## 制作指引与四阶段进度

内置流程的制作指引和运行进度共用四个顶层阶段：**策划与分镜 → 素材与配音 → 剪辑与动画 → 审阅与导出**。创意简报、风格和脚本集中在策划阶段配置。分镜侧栏只展示镜头；流程编辑保留在“流程”视图。

`WorkbenchGuide` 在开始制作前提供阶段配置；`WorkbenchProduction` 在有运行记录时保留完整阶段列表，突出正在运行的阶段。完成、跳过、失败、等候外部结果和同步失败分别按真实状态反馈。单独执行任务不缩小阶段列表，任务完成也不会将同阶段未执行的任务或其他阶段标记为完成。进度计数来自当前运行记录，不汇总或推测其他运行的完成状态。

内置示例、历史题材与通用项目统一使用视频流程：简报、风格、分镜、参考素材、视频镜头、剪辑准备和导出。`production` 为必填字段，字幕默认关闭。阶段卡片打开统一配置，模型覆盖、提示词和 Skill 位于高级设置。自定义流程按显式阶段展示；运行进度读取冻结的本次阶段定义。

点击阶段卡片始终打开统一面板，固定提供“制作设置 / 本次制作”。有配置的阶段定位制作设置；自动执行的剪辑与动画定位本次制作，镜头裁剪、运镜、转场与混音在工作台调整。制作设置按实际配置项展示分区，一次保存相关任务的生成方式、模型与提示词；高级设置仅包含当前参与生成的模型任务。本次制作保留全部执行阶段，按所选阶段过滤冻结步骤，展示真实状态、产物及本次使用的只读模型和提示词；配置操作只对有配置项的任务提供。两种视图分别保留导航选择，切换时保留表单输入。未开始与本次局部范围未包含分别展示，不以当前项目设置补造历史输入。未分组的自定义任务使用同一面板，并保留单任务执行及范围预览。

高级设置一次编辑所选任务的模型、补充要求和 Skill，切换任务保留输入；校验失败与“修复配置”直接选中相应任务并展开设置。成片页优先提供字幕、比例与分辨率，尺寸、帧率及适配方式在“更多成片设置”中调整；折叠不改变既有值，非标准尺寸与帧率按实际值显示。预览质量由画面预览标题栏直接调整，作为本机偏好保留；尚未选择时沿用项目既有的 `profile.previewScale`。调整预览质量不修改项目、制作参数或待用配置。

运行中的阶段配置保存为独立 IndexedDB 记录，按工作区、项目及任务隔离，保存原节点基线与待用节点，不进入项目主编辑会话、撤销历史或离开页面保存。这样不会增加项目修订或阻断本次结果自动保存。重开时恢复；同一任务基线被其他视图修改或删除时保留当前配置并提示冲突。下次开始前逐节点核对基线，合并待用配置、保存项目后清理本机待用记录。未运行时的阶段保存继续使用项目编辑会话，保留失败后的输入与重试。

制作前标记建议配置的阶段；执行时跟随当前任务，完成或停止后保留最近执行阶段的高亮。该标记独立于执行状态，不增加任务或阶段完成数。阶段说明通过独立的说明按钮显示，支持悬停、键盘焦点和触屏操作；查看说明不触发配置或运行。卡片在窄窗口下换行，未分组长流程可横向滚动并定位当前任务。

各步骤按依赖自动接续，完整多步骤制作成功后自动保存项目。生成期间项目修订改变时保留当前编辑与生成产物；单步或显式局部范围的候选仍可通过“应用”更新项目。“查看产物”打开实际已保存结果；历史暂停运行通过“继续”自动恢复。读取失败提供显式重试。详情与产物打开前暂停预览，关闭后保留当前制作状态。

配置问题不展示无效的原任务继续入口，而提供“修复配置”定位到阶段内对应任务。保存并重新制作会创建新运行、使用当前项目与配置执行完整流程，原运行快照及产物保留，不承诺自动继承失败运行的上游输出。可恢复的临时故障仍可继续原制作，沿用其冻结配置与输入。

## 编辑与恢复

- 镜头属性、项目设置、镜头增删／复制／排序、步骤产物应用及流程编排，使用同一编辑会话与增量命令。一次连续输入、一次缩放或节点拖动合并为一步；失焦、切换字段、保存及结构操作结束合并。
- 历史最多 50 步。新增编辑清空重做分支；撤销排序或删除时恢复原镜头 ID、内容与顺序。按钮和 Ctrl/⌘ Z、Ctrl/⌘ Shift Z、Ctrl Y 使用同一操作。
- 多选取消主镜头时，按当前镜头顺序寻找最近的剩余选择，距离相同优先前一个；取消其他已选镜头保留主镜头。此操作线性处理镜头集合，仍以本次操作的镜头为区间选择锚点。选择状态本身不写项目内容或撤销历史；已有未保存编辑仍按原流程先保存。
- 未保存内容的撤销／重做先修改草稿；从已保存状态执行撤销／重做会保存为新修订。修订号始终递增，已启动运行继续固定原快照，旧产物仍不能覆盖后续修订。
- 保存将当时的全部编辑内容作为一次 `project.update`，携带基线修订。正常存储条件下，先等待该次保存意图的 IndexedDB 事务完成，再提交项目，避免服务端已保存但重启恢复较旧的撤销内容。会话发布时直接排入原生存储事务，避免延后的渲染效果写回旧快照。保存期间的新输入保留为下一份草稿；失败不清除历史，也不自动重试业务写入。
- 同一工作区、项目及编辑会话中，持久化字段未变化时复用正在执行或已完成的草稿事务；保存仍等待原生事务完成。失败的相同快照由显式保存再次尝试，内容变化立即写入；不使用延迟写入窗口。重复选择当前镜头不重复写整份草稿。
- IndexedDB 按工作区目录和项目 ID 隔离，保存基线、当前内容、选择镜头和增量历史。事务完成的内容可在重新打开项目时恢复，包括暂时无效的空标题、尺寸或超长输入；正式保存仍由原项目契约校验。草稿不是项目备份。
- 草稿存储损坏、不可用或写入失败时显示错误，不声称已恢复／持久化；仍允许用户手动保存项目。草稿已成功读取、随后写入失败时提供“重试保存草稿”，直接重试当前快照并等待原生事务完成，不提交 `project.update` 或增加项目修订；项目内容已保存时也可重试。再次失败保留错误，处理中禁用重复操作。无法读取或解析的草稿不会被初始化的空会话自动覆盖，也不显示覆盖式的草稿重试按钮。
- 外部内容更新保留原草稿基线，阻止直接覆盖。比较框逐项显示重叠修改，可选择本地或已保存版本；非重叠的镜头字段与新增镜头合并。接受合并后使用最新修订保存；明确放弃才重新载入。保存已提交但客户端尚未收到回执时，恢复会识别与当前项目相同的草稿并保留重做历史。

跨重启草稿覆盖镜头与项目属性，也包含模板配置、字幕、背景音乐、声音处理、文稿剪辑和流程编排。共享剪辑来源／计划及流程节点／连接按 ID 保存增量变化，不在每一步重复复制原始字幕、全部历史计划或无关步骤的提示词。

### 流程画布与步骤设置

- 添加、移除、移动节点，编辑步骤属性，建立／移除连接及修改分支条件，共用项目的撤销／重做历史。移除步骤与相连的边属于同一步命令；画布阻止循环、重复连接及移除全部节点。
- 草稿格式为 2，保存流程的基线、当前图和增量历史；其他草稿格式拒绝恢复。节点名称暂时为空仍可持久化并在重载后打开画布修正，正式提交继续校验项目和图契约。
- 镜头或项目字段未完成时，可返回分镜修正，流程草稿仍留在同一会话；不会因保存校验失败而困在无法修改该字段的视图。
- `project.update` 一次原子保存流程与其他项目编辑，并校验节点唯一、连接目标和无循环依赖。图内容变化时由运行时递增流程版本；撤销／重做不回退版本，也不接受调用方指定的新版本号。原有 `workflow.save` 保留兼容。
- 本地流程草稿可合入外部修改的无关项目字段；只有当前草稿与全部撤销／重做历史都未涉及该字段时才自动合入。双方修改同一流程时，比较框以完整依赖图选择本地或已保存版本，避免分别合并节点和边产生无效图。
- 保存期间新增输入保留为下一份草稿，流程有新修改时不因先前保存完成而离开画布。失败保留输入与历史，需显式重试；步骤设置弹窗同样使用项目编辑会话，拒绝用打开时的旧内容覆盖外部较新的步骤。弹窗等待保存期间继续输入时，保留弹窗与新内容，再次确认前不启动原先请求的步骤执行。
- 画布的 Ctrl/⌘ Z、Ctrl/⌘ Shift Z、Ctrl Y 操作图历史，输入框内保留原生文字撤销；Ctrl/⌘ S 保存项目。选择、平移、缩放和 React Flow 的测量数据属于临时界面状态，不写入编排契约。
- 恢复草稿只恢复编辑内容，不自动启动或继续 Agent。已经启动的运行保留原流程版本与快照，项目随后编辑不会改变原运行的待审步骤或执行范围。

## 镜头剪辑区间

镜头支持可选的 `sourceInUs`、`sceneInUs`、`sceneDurationUs` 和 `sceneIndex`。共享入点定位原音视频，后面三项保留原场景的运镜／字幕时间与样例画面身份；旧项目无需迁移，缺省仍沿用原行为。分割保留左镜头 ID，右镜头使用新 ID 和直接切换转场，两段引用同一素材并连续取样。重排、复制或删除前固定旧镜头的样例画面索引，避免排序改变画面内容。

共享编辑函数将分割与裁剪边界对齐项目帧率，片段至少保留 0.5 秒的完整帧。真实素材的最大出点是素材时长内最后一个完整项目帧；例如 2 秒音频在 29.97 fps 下的可用出点为 1,968,633 微秒。输入精确的 2 秒合法，向下对齐；输入超出 2 秒会报错。没有音视频的二维场景允许延长，并保持原场景末态。元数据读取中、缺失、失败或超时时禁止裁剪提交，保留输入，不影响其他编辑。读取使用独立媒体元素，不改变预览的定位、音量或播放状态。

一次拖动只在释放指针时创建编辑命令，取消手势不提交。吸附默认启用，目标包含镜头边界与手势开始时的播放头；Alt 临时关闭，结果仍对齐帧。拖动片段缩至窄宽度时保持捕获手柄，释放后通过属性字段继续编辑。已保存命令的撤销／重做仍创建新修订，增量历史包含全部区间字段，可跨重载恢复。

已明确裁剪的片段严格使用编辑时长，预览与 FFmpeg 从原素材入点播放；视频尾部保持末帧，音频尾部补静音。旧项目未显式设置入点时继续保留完整长旁白。字幕在原场景时间上裁切，分割边界的连续同文字幕合并。旧项目未设置独立字幕轨时继续按场景文本估时；独立字幕轨与语音对齐规则见下文。

剪辑专项回归覆盖分数帧率分割、素材连续性、重载后重做、逐帧／十帧裁剪、拖动重排、吸附开关、最短片段指针捕获、真实素材上界、读取失败禁用，以及分割／裁剪／重排等待保存期间的新输入。字段经过 Schema 解析后可能改变键顺序，编辑内容比较按结构判断，避免误判未保存而跳过撤销持久化。

## 波形、字幕与背景音乐

`asset.waveform` 为只读接口，返回真实解码的 100 Hz 峰值、音频时长、素材 ID 与源哈希。执行层通过注入的读取器使用 FFmpeg 流式解码单声道 16 kHz PCM，按每 160 个样本聚合峰值。派生缓存放在工作区 `derived/waveforms`，按源哈希和算法版本隔离；读取前校验源文件，写缓存前再核对一次。相同请求合并，并发最多两路，取消和退出清理子进程、队列和临时文件。前端只为可见片段请求，最多缓存 16 份波形，分割片段共享源数据；失败不绘制假波形。峰值不进入项目、备份或撤销历史。

`CaptionTrack` 保存已确认的字幕。普通镜头使用 `Shot.captionTrack`，文稿剪辑将原轨固定在共享 Source，后续手工覆盖使用镜头轨。每个句段包含稳定 ID、文字和半开区间 `[startUs,endUs)`，按时间排序且不重叠。`timeBase: source` 使用音频源时间，`scene` 使用场景时间，`clip` 使用剪辑计划输出时间；普通片段沿用入点投影，非连续片段通过共享映射逐段读取。分割不破坏原时间戳。字幕编辑器显示镜头内时间，应用局部编辑时保留窗口外句段和跨边界残段；明确关闭字幕才保存空轨。无轨的旧旁白继续估时，并明确标识。预览、SRT 与烧录读取同一投影，即使旁白字段为空也可显示独立字幕，空轨则不会回退到旧旁白。

较长句段只在显示投影中分页，按各页阅读量估计页内切换时间，不改写原 `CaptionTrack`、真实句段边界或识别来源。先在原 source／scene 时间分页，再裁切到镜头，因此分割与裁剪不会重启页序；预览与 SRT／烧录共用规则。分页不代表逐词语音时间，编辑器继续显示原句段，可拆句校准或使用逐词识别。

字幕由分镜文字估时或手工编辑。可导入带时间信息的素材并保留 source、scene 或 clip 时间坐标；字幕编辑不会调用独立语音模型。

`Project.musicClips` 是项目时间上的独立音乐集合，保存项目起点、素材入点、时长、音量、淡入淡出和循环。旧项目可省略此字段；编辑快照规范化为空数组，增量命令不应用快照默认值，避免重启后撤销无关属性时清空音乐。循环从素材入点到源末尾，预览与最终 FFmpeg 混音共用对应时间和线性音量包络。音乐不混入镜头缓存，调整音乐可重用已编码画面。缩短项目只裁切投影，保留音乐数据；A2 轨展示实际源区间与循环波形。

背景音乐和字幕来源音频加入事务内的素材引用索引。引用中的公共音乐不能移除；备份包含所引用的公共素材，导入时重建独立素材 ID，并同步音乐与字幕来源引用。字幕和音乐的应用、撤销／重做及重载恢复均使用统一编辑会话。

字幕与音乐弹窗保留打开时的基线。弹窗期间同一字幕、镜头源区间或音乐集合被外部修订时，阻止旧草稿覆盖并保留输入；无关项目标题修订可以继续合并。保存失败保留当前草稿并允许重试，使用本弹窗已经提交到编辑会话的值识别自己的待保存修改，不将其误判成外部覆盖。重启后撤销无关项目字段不会清空音乐。

## 声音处理与实际混音

`Shot.audioProcessing` 保存镜头增益、降噪开关与降噪量；`Project.audioMix` 保存响度开关、目标 LUFS、真峰值及旁白侧链压低音乐的阈值、比例、起音和释放时间。`null` 或省略的项目设置使用公开默认值。项目与镜头弹窗分别确认自己的范围，取消不修改项目，应用进入统一历史；相关外部变化拒绝旧稿，无关标题保留，保存失败可重试本弹窗的提交值。

主预览、处理试听和 FFmpeg 导出共用真实 48 kHz 双声道混音。声音链读取镜头显式关联的 `audioAssetId` 旁白、项目背景音乐，以及由用户在镜头声音面板启用的视频原声。准备过程按源哈希、剪辑区间与处理参数缓存，先校验源文件再解码处理；就绪前不以旧音轨冒充当前结果。旁白按镜头区间拼接，背景音乐保留项目绝对起点、源入点、循环和淡入淡出。增益为 0 dB、降噪／压低／响度处理均关闭时，仅进行区间拼接、音乐混合与必要的格式转换，不额外归一化、限幅或降噪；超出 0 dBFS 时明确提示削波风险。

`PreparedAudioMix` 返回实际文件、SHA-256、有序 `shotDurations` 及测得的整段响度／真峰值。候选试听根据该顺序定位目标镜头，避免外部重排后沿用旧起点。主预览使用同一处理后音轨，保存中的新混音键延后准备，保留同键已就绪结果；关闭试听窗口停止本地等待，不取消可能被导出复用的后台缓存任务。异步旧键结果不能覆盖新输入，失败可明确重试。

`audio.mix.prepare` 返回实际 `AudioMixJob`，或 `{ status: 'revision_changed', revision }` 修订观察；后者不创建任务，也不修改项目。准备前、源文件读取后及缓存异步校验后都复查修订，素材归属、活性和哈希校验保持原样。主预览仅对该观察等待工作区同步，最多 3 秒并重试一次最新草稿；不会把服务端修订号强塞给旧草稿。来源或混音键变化会丢弃旧等待，真实处理／网络失败仍由用户显式重试。

电平从最终混音的真实采样计算：每 10 ms 一组左右声道峰值与 RMS，界面以 dBFS 显示“节目电平（静音前）”，整段 LUFS／真峰值来自实际分析。播放静音只控制监听，不改变混音或电平口径。该电平不同于单声道素材波形，不能由缩略峰值或字幕时长伪造。文件、分析与电平窗口是派生缓存，不进入项目编辑历史。

旧项目未显式设置媒体入点或剪辑计划时，长旁白继续按 FFprobe／媒体元数据测得的全长投影；测量按素材 ID、版本、哈希和路径缓存，不将读取结果静默保存为项目时长。文稿窗口使用同一有效时长，首次实际剪辑才写入明确的剪后时长；撤销后恢复旧草稿值与原有完整旁白行为。

### 视频原声

旧项目及新建镜头默认关闭视频原声。原有声音处理版本 1 保留旁白增益和降噪；版本 2 增加 `videoAudio: { enabled, gainDb }`，原声增益范围为 -60 至 +18 dB，关闭即静音。使用视频的首条音轨；原声与旁白分别处理，再与背景音乐混合，旁白侧链压低音乐只由旁白触发。项目的总响度设置继续作用于最终混音。

原声按 `resolveShotSpans` 的 `videoInUs` 采样，旁白按 `audioInUs` 采样；两者使用同一全局 48 kHz 样本边界。分割、裁剪、文稿删除和恢复源窗口保持对应视频来源；短音轨末尾补静音，不拉长镜头。视频中晚于画面起点的声音保留起始空白，波形使用相同的媒体时间原点。有效视频没有音轨时显示提示并保留可播放的静音混音；文件缺失、哈希变化或冻结的剪辑来源不匹配仍明确失败。

图解模板覆盖画面时，已启用原声的视频仍参与真实素材时长读取；单镜头、批量裁剪和 EDL 尾部延长共用该来源边界。关闭原声后，保留的视频继续作为闲置来源，不限制图解时长。

时间轴在至少一个镜头启用原声时增加独立 A2 原声轨，显示真实波形和视频源入点；有背景音乐时音乐轨顺延为 A3。未启用原声的镜头显示关闭或未关联视频的状态。所有片段沿用原有选择、拖动与分割行为。

试听使用未提交的面板设置，取消不保存；应用为可撤销命令，失败后保留输入和两次明确应用的历史。涉及原声时同时比较视频绑定、源窗口和素材版本／哈希／路径等身份；仅调整旁白仍允许无关的视频修改。原声参数随草稿、项目备份和恢复保留，导入为新的素材编号。已启动导出读取冻结的项目快照。

混音派生缓存使用算法版本 3，并纳入原声内容、源区间及增益；波形缓存使用媒体原点版本 2，按内容及素材类型隔离。旁白声音处理版本 1 的采样原点保持原有含义。当前仅选择首条原声音轨，不提供多音轨选择，也不把视频原声自动转成旁白资产或语音识别文本；已关联旁白的文稿删除仍可同步裁切原声和画面。

专项验证使用真实 MP4／AAC／WAV，覆盖原声默认关闭、独立增益、静音、延迟起点、非连续剪辑、配音与音乐混合、旁白侧链隔离、实际 MP4 导出和源文件变化保护。浏览器检查实际播放的 WAV 采样、原声波形入点、试听不保存、保存重试、撤销／重载、外部替换视频、无音轨恢复，以及分割／EDL 删除后整项目备份恢复。

## 文稿剪辑与源窗口恢复

“文稿剪辑与停顿清理”先在本地选择词句、手选时间范围或勾选实际检测的停顿，再用生产画面和处理后混音试听候选，确认后一次应用。逐词选择同时要求 `alignment: speech`、`granularity: word`、源音频 ID 与 SHA-256 匹配；手工编辑或估时结果即使残留 word 标记，也仅按句段／手选处理。旧识别来源不匹配时禁止用其词句区间剪辑，仍可明确手选范围。识别句段之间的间隙不等于实际静音。

停顿由真实源音频检测阈值、最短时长和两端保留量生成。检测前保存当前草稿并核对修订，结果再按源 ID／哈希校验，通过音频分段映射到当前镜头输出时间。候选默认不选；调整参数会取消旧等待并清除旧候选与选择，检测不会自动写项目。删除区间向外对齐当前项目帧率、合并重叠区间，剪后至少保留 0.5 秒，画面、旁白、场景和字幕同步删除；背景音乐不随镜头内容前移。

一个逻辑镜头通过 `Shot.clipEdit` 引用共享的 `Project.clipEditSources`／`clipEditPlans`。Source 固定原时间、媒体 ID／哈希和一份完整原始字幕；Plan 按微秒保存保留分段，各段具有原始、音频、视频与场景入点。已有来源和计划不能原地改写，进一步编辑分配新 ID；分割／裁剪只切换计划输出窗口，不重新按导出帧率量化内部切点。预览、波形、字幕、混音与导出通过同一映射读取区间，增量撤销与草稿保留来源和计划关联。

EDL 视频预览按当前保留区间接收实际解码帧，同步复制安全帧再绘制，避免独立原生播放提前进入已删帧。跨切点强制定位；不同源帧率的准确采样与编码一致，无 `requestVideoFrameCallback` 时使用逐帧定位回退。真实解码回归覆盖：30 fps 删除一帧后连续播放不出现已删旧帧，并与 MP4 编码帧核对；24→30 fps 的区间内部采样一致；无视频帧回调时的回退仍正确跳过删除区间。

“恢复源窗口”只恢复当前分割／裁剪片段对应的原音视频与字幕，不展开到整个父镜头；当前标题、样式与其他镜头保留。弹窗固定打开时的镜头、帧率、计划、字幕及素材版本／哈希，相关变化会保留选择并拒绝覆盖，无关标题或顺序变化可以合并。候选预览不写项目；应用或恢复各产生一步命令。应用已加入草稿但保存失败时锁定这份选区，重试仅保存同一结果，不再分配计划或新增撤销步骤。

素材引用索引保护剪辑 Source 所需的原素材。项目备份统一使用格式 4，复制全部恢复所需素材；导入校验格式、文件及 SHA-256，重建素材编号并同步剪辑来源、计划和字幕来源。混音、波形和电平缓存可重建，不作为原素材备份。

## 单镜头候选与独立媒体入点

`shot.regenerate` 固定当前修订、目标镜头、模型、补充要求与原镜头基线。实际执行仅包含目标镜头；文本须恰好返回一条，媒体须恰好返回属于目标镜头的一份相应素材。模型可以沿用该工作流步骤的已配置模型，但不能在缺少对应模型时以旧素材冒充新生成。锁定镜头需要先解锁。视频把本次调整要求与台词、声音要求一起提交。

合成的 `regenerate` 步骤支持分镜、图片和视频，沿用检查点、操作标识与远端回执。完成事务只写候选和素材，应用前不修改项目。视频候选核对真实画面、音轨和时长，应用时使用视频原声并清除独立旁白及旧字幕。关闭窗口只停止本地观察；恢复不重复提交已完成或已提交的远端任务。

文本应用只合并勾选的标题、旁白、画面要求或时长，时长默认不选。媒体应用只替换对应关联；应用图片时移除优先显示的视频关联，让选中图片可见。应用前逐项核对相关字段与基线，并再次核对当前项目修订；其他镜头、项目名称及未选字段的人工修改会保留。应用结果作为一次 `应用镜头候选` 命令保存，支持撤销／重做和重载恢复；校验失败保留当前内容与对比窗口。

`Shot.audioInUs`、`videoInUs` 为可选独立入点，缺省回退共享 `sourceInUs`。替换音频只将新音频入点置零，替换视频只将新视频入点置零，另一媒体、场景和字幕原数据保持。源时间字幕随有效音频入点投影；旧语音字幕在音频身份改变后提示重新对齐。分割推进显式独立入点，共同裁剪按共享入点差同步推进；最早共同入点不能使任一已关联媒体落到负时间。真实素材时长先缓存，再投影为共同出点上限。预览、波形、字幕和 FFmpeg 使用同一规则；显式音频入点的镜头固定当前时长，不触发旧项目的长旁白自动延长。

## 旧资料数据兼容

工作台已移除资料管理、事实主张与镜头引用的编辑入口，流程画布也不再提供资料节点类型。预览和成片不显示引用编号、不保留引用页脚，`timeline.json` 不再附带引用目录。旧的 `claims`、`researchSources`、`referenceDisplay` 和镜头 `claimIds` 仍可读取、备份和恢复，不清除历史数据；冻结运行的既有产物可只读查看。

制作配置统一由工具栏“制作设置”进入。创作要求、视觉风格与系列模板归策划分区；参考素材、参考音频、生成声音要求、背景音乐与项目混音归素材分区；字幕开关、字幕样式与成片规格归导出分区。自定义流程始终保留这些项目级配置，其任务覆盖按显式阶段组织。

参考音频记录在 `workflow.production.referenceAudioAssetIds`，由素材与配音分区选择本地 WAV / MP3 文件并导入项目素材；每个文件不超过 15 MB。Seedance 调用在 `content` 中发送 `audio_url` 与 `reference_audio`，音频参考场景的图片使用 `reference_image`。Seedance 2.0 需同时提供参考图片，最多 3 段、总计 15 秒；2.5 可仅提供音频，最多 10 段、总计 30 秒。运行快照保留本次音频素材，待用配置用于下次制作；备份恢复会重映射引用，当前项目使用中的音频受素材占用保护。


“我的项目”卡片提供备份操作，备份当前已保存的项目及其引用素材，完成后展示真实备份位置。备份期间禁用重复提交，失败后可重试；导入备份继续从项目列表进入。

保存配置不要求模型已就绪，启动制作时校验模型。打开附属工具前通过同一配置保存路径保存输入，成功后关闭设置并打开工具；失败时保留表单、选中分区与输入。运行中保存继续使用待用配置，冻结的本次参数保持不变。取消只关闭当前表单，已保存的配置与编辑历史继续保留。

项目字段按打开设置时的基线保存：其他视图对无关字段的修改继续保留；同一字段被双方修改时保留本机输入与待用配置并提示冲突，当前项目保留其他视图已经保存的值。

## 科普模板与批量导出

`Shot.sceneTemplate` 是可选公开契约，包含流程讲解、双侧对比和柱状数据图三种结构；共用标题、配色和显现动画设置。旧项目不填时沿用原画面。示例内容明确标识，不作为已核验事实。Canvas 预览与本地编码共用绘制器，模板激活时不读取闲置图片／视频，但保留其关联以便切回原画面；旁白和字幕继续生效。模板切换保留原场景时钟，分割与裁剪后动画进度连续。手动选择或应用新的图片／视频候选会退出模板，替换音频保持模板。

模板编辑纳入统一草稿与增量命令。未完成的空标题、空标签或负数据值可在草稿中恢复，正式保存仍由公开契约校验。镜头候选的相关字段检查包括模板，防止旧视觉产物覆盖新模板；按语义比较结构，不因对象键顺序误报冲突。

`render.batch.start` 固定保存修订、每个目标规格和实际消费的素材快照。最多八个目标，每项使用自己的运行、缓存与输出目录，串行本地渲染，不调用模型或计入模型费用。模板不会冻结闲置视觉素材；有视频时不冻结被覆盖的图片；字幕来源音频只作来源标识，不额外作为渲染输入。

批次公开记录通过 `render.batch.get`／`list` 按需读取，列表每页最多一百项。关闭窗口保留后台执行；`cancel` 等待在途任务停止，`resume` 继续失败、中断或取消项，成功项先验证产物哈希再跳过。执行组件重启只标记为中断，由用户显式继续；后续项目编辑不改变原批次。子运行的继续／停止同样路由到所属批次。

每批次和每目标使用独立的所有权标识与产物回执，发布采用临时复制和重命名；既有非本批次文件不会覆盖。输出损坏可用原快照恢复相应目标，其他成功项保留。批次完成、部分失败与取消均可从导出面板重开，查看各项状态与四类输出路径。

## 多选与批量编辑

列表、V1 和 A1 共用本地 `ShotSelection`，保存有序 ID、主选与范围锚点；选择不写入项目命令。修订或撤销删除主选镜头时，先裁剪失效 ID，再用剩余主选驱动属性、素材读取及单镜头剪辑，避免高亮与操作目标错位。显式空选择保留为空；全选与清除快捷键只作用于列表和时间轴，表单保留原生文本选择。

批改窗口固定打开时的目标与基线；只比较将要修改的时序／运镜／字幕／模板外观字段，无关内容按最新草稿保留。时长读取去重且最多四路并发，独立媒体元素不改变预览；素材 ID、类型、版本、哈希和路径换新后首帧阻断提交，应用前再次核对。音视频时长必须读取完整，公共出点沿用较长来源尾部，短路素材按既有规则保持末帧或补静音。图解启用时不读取闲置视频。

所有目标先校验，再生成一个不可变载荷并调用一次 `session.edit`。锁定目标列名并整批拒绝；复制展开来源当前有效字幕样式，仅同步双方已有模板的配色与动效，保留模板类型、内容、媒体、引用和字幕句段。已加入草稿而保存失败后锁定本次表单，重试只保存，不再新增命令；关闭弹窗保留父级保存与草稿。

拖拽将所选镜头按原顺序作为一组插入移除组选后的插槽；前后移动让每段连续选择跨过相邻未选镜头；副本紧随各原镜头。结构操作先固定全部旧镜头的 `sceneIndex`，背景音乐仍位于项目时间。删除等待保存期间重新检查所选镜头完整内容，避免删除后续输入。增量历史解析不注入快照的默认资料／风格，兼容清理旧解析器在命令两侧写入的相同字段，保留真实变更。

## 字幕样式与系列模板

`Project.captionStyle` 为项目默认，`Shot.captionStyle` 为整镜头覆盖；`null` 或省略表示继承，旧项目两级均省略时保留旧排版。受控样式包含无衬线／衬线字体、短边字号比例、400／700 字重、文字／背景六位颜色、背景透明度、标题下方或底部位置及每页 1–3 行。预览与烧录共用字体目录、测量、分页和安全区；混用样式时生成逐事件 ASS，SRT 仍只表达文字与时间。逐词识别时间戳不等于逐词动画，当前不提供任意字体导入、描边或逐句局部样式。

`SeriesTemplate` 通过分页库和修订检查保存、编辑、归档及恢复，只保存风格文字、字幕样式与新镜头画面预设。新项目创建固定所选修订；现有项目应用固定已预览的模板快照和打开窗口时的镜头范围，后续库修订不追溯项目。可选清理未锁定镜头字幕覆盖、同步现有模板配色与动效；不会改模板类型、正文、图表数据、引用或媒体。新建手动／生成镜头读取项目预设，已有镜头保留自身内容。

应用进入统一编辑历史、草稿和备份。重试按项目范围及每个实际触及镜头保留本弹窗最近提交值；范围关闭期间的外部更新不会被认领，锁定镜头和开窗后新增镜头也不进入同步范围。未完成的非法颜色保留输入并显示最后有效预览，保存仍须通过公开契约。项目摘要保留默认字幕样式，素材引用索引与项目更新保持事务一致。

## 角色、模型参数与费用

`CharacterProfile` 是工作区可复用记录，保存名称、文字设定、最多四张公共参考图、修订和归档状态。`Shot.characterIds` 可省略，最多八个，选取顺序保留。保存角色和项目时校验有效公共图片及角色状态；已被项目引用的角色不能归档，引用中的公共图不能删除，素材列表同步显示“使用中”。归档角色保留图片以支持恢复。草稿中已选角色随后被归档时，仍可取消该项而保留其他人工编辑。

新运行只解析实际选中的角色 ID，并固定角色与图片元数据快照。普通脚本生成保留人工绑定，不让模型响应替换角色 ID；后续媒体步骤按各镜头使用对应子集。文字模型读取选中角色的名字和文字设定，不把文字设定声称为视觉输入；支持的图片／视频适配实际发送经哈希校验的图片。单图上限 20 MiB、去重总量 64 MiB，供应商张数／格式限制和不支持的映射在网络提交、活动日志和费用记录开始前检查，明确失败，不误报为外部提交未知。单镜头与普通步骤的产物应用均核对当次角色修订及参考图哈希；无关角色更新不阻止应用。

OpenAI 兼容图片参考使用当前图片编辑 JSON `images` 数组，最多 16 图；视频兼容协议沿用已接服务的单参考输入。Seedance 首帧方式只接收一图，多图需要显式 `characterReferenceMode: reference_image`；自定义 HTTP 与 ComfyUI 必须配置角色图片数组映射，不能静默省略。各协议仍需通过用户服务验证可用模型、限制及计费。角色及公共参考图随项目内容备份保存；导入创建新角色／素材 ID 并同步镜头绑定，文件使用资产 ID 的安全哈希命名，多个候选的同名文件不会覆盖。备份缺失文件明确失败，不生成无法完整恢复的清单。

`getModelParameterFields`、`validateModelParameters` 和 `requestModelParameters` 统一表单、保存边界、运行快照和实际请求。连接显式选择文本、图片或视频一种类型，拒绝混合生成能力。表单与高级 JSON 双向同步，保留未知服务参数，过滤已识别的其他能力字段和内部配置。支持文本温度／输出上限、图片尺寸／质量、视频尺寸／时长／比例。视频生成固定请求声音。Ollama 参数进入 `options`；DeepAgent 的温度、输出上限和高级文本参数也进入真实模型请求。

模型用量保存运行、步骤、镜头、模型与价格快照。文本调用保留服务实际返回的 Token 指标，图片和视频按请求数量或时长估算；未知计量保持未知，不以估算代替服务账单。人工核对金额、币种与备注通过修订检查独立保存。

遗留 `submitted` 费用在进程启动时转为未知，不声称继续扣费；恢复确认已有响应后更新同一记录，已完成调用与重放不新增费用。未知提交不会自动再次 POST。工作区费用记录不进入项目内容备份，模型凭据不写入费用快照。

费用页面按既有 `runId` 将记录归档为制作任务，单镜头候选等独立运行也各自成组；任务重做保留新的任务 ID 与来源任务关联。任务汇总先聚合全部记录，再分页任务，不依赖浏览器已加载多少费用。任务名称、项目名、步骤名和镜头名优先读取运行快照，避免后续重命名改写历史含义；原运行／快照不可用时仍显示已保存账目和原始编号。此处归档表示费用按任务保存和查阅，不新增删除任务或自动清理账目的操作。

任务详情独立分页加载费用，并可展开操作标识、请求计量、服务返回计量和当次单价。核对实付后直接采用服务端返回的已提交记录，更新已加载的较早页面及任务卡片；后台刷新仍只读取第一页。不同任务的延迟响应不会互相覆盖，返回列表保留筛选、已加载任务和原按钮焦点；实付修订冲突保留金额与备注，不覆盖外部登记。

费用界面使用汇总、项目筛选、平面任务表格和按需明细。真实生产组件覆盖明暗主题、窄窗口、原生表格语义、焦点恢复与减少动效，排版和尺寸消费统一主题角色。任务页与明细页都保留自己的筛选、游标和显式重试语义。

## 工作区刷新与项目读取

工作区摘要与当前项目详情独立读取。打开已知项目时立即请求项目详情，摘要更新可在后台完成；已完成且仍匹配当前选择的响应可以先显示。切换到另一个项目后，迟到的旧项目响应只结束自己的读取，不替换当前项目。

摘要和每个项目分别合并刷新请求：同一资源至多有一次读取正在执行，重叠请求共享下一次读取。调用方等待的是自己提出刷新后开始的读取；持续事件不会反复作废已经完成的有效响应。项目详情继续使用修订与素材版本条件，并复用未变化的记录引用。

成功的 `project.update` 回执经过契约校验，且仍属于当前项目、修订更新、没有在途或失败读取时，可作为下一次条件读取的项目基线。素材版本和最新运行仍由真实读取更新；外部较新修订仍会传回。服务端同步项目保存复用同次请求已读取的当前基线，校验与修订冲突检查照常执行；最新运行通过既有项目索引读取，不扫描其他项目的执行历史。

当前项目读取失败时显示原因和“重新读取项目”入口。错误由对应项目拥有，其他摘要读取成功不会清除它；重读仍经过同一读取队列。现有编辑草稿、修订检查与制作提交保持原有语义。

回归使用真实项目接口，在浏览器响应边界控制延迟，并运行实际通知防抖计时器，覆盖后续刷新仍未完成时显示项目、摘要延迟、快速切换后旧响应迟到，以及读取失败后的手动恢复。请求合并参考 [SWR 的去重原则](https://swr.vercel.app/docs/advanced/performance)，实现复用当前本地 RPC。

## 视频缩略图与真实媒体基准

镜头列表和时间轴只为实际进入视口、至少显示四分之一且可见宽高均不小于 16px 的预览读取视频帧；两处相同请求共享结果。复用现有准确定位控制器，取帧后立即清理视频源、监听与帧回调；全局最多两路缩略图解码，主预览保留独立的正常播放路径。滚出视口取消该消费者，最后一个消费者离开时移除排队任务或中止正在解码的任务；中止任务真正结束前仍占用并发槽。

内存缓存按素材 ID／版本／哈希／路径、微秒源位置与预览尺寸分键，LRU 最多保留 48 帧及 800 万实际像素（约 32 MB RGBA，不包含显示画布与外部引用）。超预算单帧不缓存，失败不缓存；迟到的旧任务不能替换新请求。离屏显示画布收缩为 1×1，并释放组件持有的帧引用，滚回时重新绘制。缓存只保存真实原始媒体帧，标题、字幕、图表和引用继续由当前场景配置绘制；不写项目、数据库、备份或撤销历史。图片读取同样按视口触发，沿用原有图片缓存。

预览组件只比较自身镜头、时间、素材、回调及实际消费的项目字段，避免其他镜头标题变化导致所有缩略图重新渲染。数字引用模式仍依赖全部镜头，为引用预留一致的字幕空间；字幕样式、资料／主张、共享剪辑来源／计划变化仍会刷新。`scene-preview-invalidation.spec.ts` 渲染真实组件，以画布像素、错误状态和回调验证这些失效边界。

运行 `pnpm test:e2e tests/e2e/media-performance.spec.ts --workers=1 --repeat-each=2`，按项目说明先准备固定版本 FFmpeg。测试创建隔离项目与真实的 5 秒 H.264 1920×1080、30 fps 文件；50／200 个 1 秒镜头共享该素材，但使用相差 20 ms 的实际视频入点。预览规格为 1920×1080、比例 0.5，窗口 1536×960；没有调用模型服务。真实像素、源入点变更、滚出回收、滚回恢复及取消后重试另由 `thumbnail-loading.spec.ts` 验证。

测量记录打开到画面可用、选择与定位反馈、视频帧回调、页面刷新、带源视频元素及进程工作集。动作耗时包含自动化开销，帧回调使用短窗口，工作集可能包含共享页；它们不能分别冒充精确落屏延迟、长期分位数或私有内存。浏览器堆与帧数也不能证明物理 GPU 表现。

性能夹具单独关闭 trace，并记录实际浏览器版本、trace 模式、原始样本及所有控制台／媒体错误；普通功能回归保留失败 trace、严格像素与顺序断言。并发回归、录制及不同机器的测量不能直接混作同一基准。每次运行生成 `real-media-metrics.json`；资源上限仍要求带源视频元素不超过主预览加两路取帧。

## 可重复基准

运行 `pnpm benchmark:workspace`。夹具为 10／50／200／1000 镜头，每组 1000 条素材、200 次运行、每次 100 条事件，带持久化活动结果；全部在临时目录创建并清理，不使用日常项目或真实模型。素材路径是读取基准元数据，不进行媒体解码。报告包含接口原始样本和完整编辑保存（5 次预热、20 次计时，含 JSON 序列化），每次保存携带当前修订和完整编辑内容。`selectionToggle` 单独测量从全选中取消主镜头的真实选择函数，5 次预热、20 次计时，每次使用同一输入；不含界面和序列化耗时。

`editor-performance.spec.ts` 单独记录 200／1000 镜头的打开、编辑后撤销、末镜头选择和重载恢复耗时，同时验证草稿、选择与撤销／重做；不设易受机器与自动化查询开销影响的延迟断言。`draft-write-efficiency.spec.ts` 验证真实 IndexedDB 写入次数、原生事务完成屏障、失败重试和项目隔离；`project-save-refresh.spec.ts` 验证保存后的条件读取及已加载项目读取失败后的显式恢复。

`shot-selection-scaling.test.ts` 在 5000 镜头选择中约束重复全数组查找次数，同时验证主镜头、锚点、顺序和输入不变性。`asset-page-references.test.ts` 验证 100 项素材页只执行一次角色引用查询，以及分页、归档保护和外部角色修改后的即时更新；普通工作区基准不包含角色库，不能单凭其 `assetPage` 耗时代表大型角色库。`draft-retry.spec.ts` 用真实事务中止和完成屏障验证纯本机草稿重试、已保存内容、重复键盘操作和未读草稿保护。

报告区分 Runtime 内部读取／序列化、IPC 或 HTTP 传输、React 确认和媒体播放。初始化耗时、整个混合负载后的堆采样和单接口结果分别记录，不将未回收垃圾当作常驻内存。每份性能结果须同时保留源码提交、平台、CPU、内存、分辨率、媒体规格、工具版本与采样方式。工作区基准输出 HEAD、未提交修改标记、关键源文件哈希及采样边界；浏览器基准另保留窗口、浏览器版本和 trace 模式。

多独立源和长时测量见[外部服务与性能验收](release-validation.md#多独立媒体与长时播放)。是否引入列表虚拟化、代理媒体或其他优化，应由对应环境中可重复的瓶颈决定。

## 制作步骤详情

制作记录通过“查看步骤”按需打开详情。冻结的步骤列表与当前项目流程分开保存；步骤状态取自原生 LangGraph SQLite 检查点，已经保存产物但尚未推进检查点时保留待执行状态与说明。输入、输出、历史版本及所选步骤的日志分别读取，打开列表不预先传输全部运行产物。

| 接口 | 数据边界 |
| --- | --- |
| `run.inspect` | 运行摘要、冻结步骤和原生检查点状态；可选 `nodeId` 额外读取该步骤的模型、Skill 与配置快照，不展开产物。 |
| `run.step.payload` | 明确选择 `input` 或 `output`。输入是步骤开始时的上下文，不用当前项目替代；没有记录时返回不可用。 |
| `run.step.versions` | 同一项目、同一步骤 ID 与种类的产物版本元数据；游标分页，最多 100 条，不读取历史结果正文。 |
| `run.events` / `run.activities` | 可按 `nodeId` 过滤；节点 ID 自带冒号或包含百分号／下划线时仍按完整命名空间匹配，活动不展开结果正文。 |
| `run.diagnostics` | 用户明确导出所选运行的脱敏快照、检查点摘要、全部捕获活动／事件及步骤输入输出，流式写为本地 `.json.gz`。 |

详情查询按资源合并刷新，已完成响应可以立即显示；切换步骤或版本后，较早响应不能替换新选择。React Strict Mode 的效果重新挂接复用同一次读取，失败后提供重试入口，不重复提交业务操作。媒体只为所选产物创建预览元素；版本列表只读元数据。

历史产物可并排比较，再转入项目中查看与应用。应用复用现有修订、角色、素材和人工内容保护，并通过统一编辑会话保存为可撤销命令；已有人工修订时保留输入与产物窗口，拒绝覆盖。媒体应用从所选步骤的实际输入和结果重建该步骤状态，避免把下游最后的画面当作较早步骤的结果。损坏／被更换的素材会阻止应用。

界面复用现有 Primitives 和颜色、字号、间距、圆角令牌，底部操作区固定、正文独立滚动；支持键盘选项卡、焦点恢复、明暗主题和窄窗口。设计参考 [LangGraph Agent Chat UI](https://github.com/langchain-ai/agent-chat-ui) 的活动与执行状态表达，状态与恢复继续使用 [LangGraph 持久化](https://docs.langchain.com/oss/javascript/langgraph/persistence) 和当前本地 IPC。
