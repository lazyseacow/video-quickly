# AI Story 能力融合执行方案

建议优先吸收 AI Story 在创作资产、提示词调试和系列生产方面的产品设计，沿用 Video Quickly 现有的桌面架构、四阶段制作流程和持久化执行能力。首批交付聚焦角色一致性：让项目选择的角色真正贯通分镜绑定、参考素材和视频请求，再逐步扩展到提示词实验与分集制作。

## 策划时两个项目的能力差异

AI Story 围绕故事视频组织创作，源码中有剧本与分集、作品与项目、提示词集、资产抽取和多宫格素材等明确的业务对象。Video Quickly 已有通用制作、编辑、媒体处理和本机恢复基础，融合重点应放在上层创作能力。

| 范围 | AI Story 的实现证据 | Video Quickly 策划时状态 | 融合判断 |
| --- | --- | --- | --- |
| 创作资产 | 从文本抽取资产，检索已有资产候选，按项目绑定并注入生成上下文 | 有角色库、角色参考图和镜头绑定；尚缺项目角色池及场景、道具的统一创作上下文 | 最高优先级，先贯通已有角色 |
| 分镜生成 | 细化主体、场景、构图、光照等提示内容 | 有 JSON 解析、稳定镜头身份、锁定和剪辑保护；新镜头不会自动建立角色绑定 | 补充受控的语义引用和生成质量约束 |
| 提示词生产 | 模板集、变量、快捷片段、调试会话、版本和可复用中间产物 | 有节点提示词、Skill 版本、运行快照和历史产物比较；缺少独立实验空间 | 复用执行器补调试入口与模板管理 |
| 系列生产 | 剧本分集、作品归属、批量建项目、同作品分集串行队列 | 系列模板复用视觉配置，尚无作品与分集领域对象 | 单独增加关系与队列，保留现有模板语义 |
| 媒体探索 | 多宫格图片生成、切片和图片编辑 | 有素材、镜头候选、对比、按字段应用和本地媒体工具 | 后续作为可选素材工具 |
| 外部剪辑 | 有剪映草稿服务与接口 | 有成片、字幕和时间线导出，以及完整本地剪辑能力 | 先验证目标剪辑软件的兼容性 |
| 调度与恢复 | Django、Celery、Redis 和项目阶段状态 | LangGraph、SQLite 检查点、逐镜头回执、受控并行与取消 | 继续使用当前执行基础 |
| 模型管理 | 多供应商、批量配置与模型发现 | 已有模型发现、协议参数、连接检查、用量及费用记录 | 复用现有实现，按真实协议缺口补充 |

### 技术适配

AI Story 的配置使用 Python、Django、Celery、Redis 与 Vue 2。当前项目采用 Node.js 24、TypeScript、React、Electron 和 SQLite。首期复用现有 Zod、LangGraph、素材库和媒体工具，预期无需新增运行时依赖。外部配置见 [Python 依赖](https://github.com/xhongc/ai_story/blob/e859bf39eb1e9669153888cc78c3f57a81c771cd/pyproject.toml)与[前端依赖](https://github.com/xhongc/ai_story/blob/e859bf39eb1e9669153888cc78c3f57a81c771cd/frontend/package.json)。

以下实现细节需要转化为适合当前项目的需求：

- 对方默认分镜提示词包含固定亲子题材、服装和画面文字要求。应重新编写适用于通用视频的创作模板，将题材与风格作为输入。见[默认分镜提示词](https://github.com/xhongc/ai_story/blob/e859bf39eb1e9669153888cc78c3f57a81c771cd/backend/apps/projects/default_promot/storyboard.md)。
- 对方声明多种负载均衡策略，项目模型也有相应枚举；本次核查尚不足以确认四种策略均有完整调度和恢复保证。当前项目先维持显式模型选择及冻结配置。见[项目模型配置](https://github.com/xhongc/ai_story/blob/e859bf39eb1e9669153888cc78c3f57a81c771cd/backend/apps/projects/models.py)。
- 对方剪映草稿服务中，背景音乐片段存在固定五秒的简化处理，部分缺失素材会被跳过。新导出器必须以当前实际时间线为依据，明确报告不支持的效果。见[剪映草稿服务](https://github.com/xhongc/ai_story/blob/e859bf39eb1e9669153888cc78c3f57a81c771cd/backend/core/services/jianying_draft_service.py)。
- 多宫格切图具有明确的源图、行列、间隔、外边距和裁剪区域数据，值得参考；成图是否符合网格、角色是否一致以及是否节约费用，需要内容样例验证。见[切图服务](https://github.com/xhongc/ai_story/blob/e859bf39eb1e9669153888cc78c3f57a81c771cd/backend/core/services/multi_grid_image_service.py)。

## 分阶段执行

### P0 建立验证基线

目标是让后续变更能与当前行为比较，并保护工作区已有修改。

1. 记录现有修改及相关测试结果，按功能范围组织后续差异。
2. 准备三组可重复样例：单角色故事、多角色连续场景、已有剪辑与锁定镜头的项目。全部使用本地夹具，避免分析阶段产生模型费用。
3. 记录四阶段展示、自动接续、镜头角色绑定、候选应用和备份恢复行为。
4. 同步本次会影响的文档差异：`development-plan.md` 的备份说明仍提及格式 1、2、3，而 Runtime 与 `durable-execution.md` 当前统一使用格式 4。后续以实际契约为基线更新说明。

验收：形成可复现的相关功能基线，区分已有失败与新增问题。

### P1 打通创作设定与分镜引用

首批目标：用户在项目中选择现有角色后，自动分镜可以把正确角色绑定到新镜头，后续图片和视频请求使用对应参考图。

#### 项目创作上下文

增加可选的项目创作上下文，先承载项目角色池、固定场景描述、关键道具和连续性要求。角色池引用现有 `CharacterProfile`，不改变公共角色库的职责；场景与道具首期使用项目内文字设定。

开始运行时，固定项目角色池与已有镜头实际引用角色的并集，以及对应角色修订和参考图元数据。当前快照主要从镜头绑定收集角色，这一步必须同时调整，才能支持从空分镜创建的新镜头。

文本抽取结果使用本次上下文内的语义键。已有角色由 Runtime 根据冻结白名单映射为真实 ID；模型返回的未知键或伪造素材引用应在解析边界拒绝。新发现的人物先保存为本项目的文字设定，进入公共角色库仍由用户主动保存。

首期对新增人物提供文字连续性约束；需要真实角色参考图时，使用已有角色库和已选参考素材。自动生成角色参考图、场景图与道具图放入后续素材扩展。

#### 分镜生成与保护

在分镜输出中增加受控的创作对象引用，继续沿用稳定镜头 ID、锁定镜头保护和剪辑设置保护。普通重新生成默认保留人工绑定，显式调整角色时才提出变更。

分镜提示统一组织主体、动作、场景、景别、构图、光线和声音要求。首期继续生成现有 `visualPrompt`、`narration`、`soundPrompt` 和 `durationUs`，只为确有独立编辑需求的数据增加字段。生成模型的运镜描述与本地 `panX/panY/zoom/keyframes` 分别表达各自含义。

项目创作上下文随步骤产物进入 `run-project`。完整制作沿用现有自动接续和最终事务应用，局部生成沿用候选应用；不会向制作流程加入人工审核等待。

#### 界面入口

项目角色池和连续性设定放入“制作设置 → 创作要求”。镜头属性继续展示实际绑定；自动建议的更改通过现有编辑历史应用，支持撤销。四个顶层阶段及其顺序保持现有约定。

主要改动入口：`packages/contracts/src`、`packages/runtime/src/workflow-prompts.ts`、运行快照与产物应用、`characters.ts`、`project-readiness.ts`、制作设置、分镜编辑与项目编辑会话。

验收条件：

- 从空分镜生成的镜头可绑定项目已选角色，实际媒体请求包含对应设定和参考图。
- 不同镜头只发送各自需要的角色；未知引用在外部提交前报错。
- 人工绑定、锁定镜头、素材关联和剪辑窗口受到现有规则保护。
- 运行期间修改角色或项目设定，不改变该次运行的输入；后续应用执行修订检查。
- 取消、恢复和重放沿用原回执，重放不产生外部调用。
- 创作上下文、角色引用和素材能完整备份恢复。

### P2 增加提示词预览与实验

目标是允许用户用一个步骤或一个镜头验证提示词，再将有效配置保存为可复用版本。

1. 增加离线预览：选择任务、上下文和草稿提示词，调用与正式执行相同的构建逻辑，显示实际拼接内容、变量来源和引用校验结果。预览不提交生成请求。
2. 增加独立实验会话，记录基线项目修订、草稿配置、模型、Skill 版本、最终提示词、输出、耗时和用量。试运行显式提交，并显示其实际费用记录。
3. 试运行复用现有执行器、检查点、媒体回执和取消能力，以独立运行身份冻结草稿参数。限制到目标节点或镜头，禁止自动应用到正式项目或接续完整制作。
4. 允许选取已保存的上游产物作为输入，执行现有类型与素材完整性检查。图片、视频实验优先复用镜头候选与对比界面。
5. 增加轻量提示词模板和快捷片段，支持任务适用范围、收藏、追加或替换，以及不可变版本。保存模板与应用到项目是两个明确动作。
6. 变量先支持受限字段路径和字面值，复用现有绑定解析能力；模板内容始终作为数据处理。Skill 继续承载方法与工具权限，子流程继续使用现有工作流模板。

入口优先放在任务高级设置与现有工作室中，避免为每项能力增加侧栏页面。运行记录保留实验来源，正式制作与实验可分别筛选。

主要改动入口：`workflow-prompts.ts`、Runtime 运行准备与详情、提示词会话文档、现有 Skill 与任务设置、`RunInspector`、镜头候选界面和费用记录。

验收条件：离线预览零生成请求；相同快照的预览与执行构建结果一致；试运行不改项目；版本更新不改写旧运行；中断恢复不重复提交；用户可查看产物后再主动应用。

### P3 增加作品与分集生产

目标是把一组相关项目组织成作品，并按明确顺序批量制作。

增加作品和分集关系，分集关联现有项目并保存集数、标题及原始文案。系列模板继续作为视觉配置预设使用。作品级角色和风格作为新分集的默认输入，已有项目通过显式同步应用更改。

首版队列采用顺序执行：

- 入队记录项目 ID、修订、顺序和请求身份，同一项目的重复入队请求返回已有活动项。
- 开始该项前核对项目修订，再通过现有运行准备逻辑冻结参数。排队期间项目变化时，将该项标记为需要处理，由用户明确刷新输入后再启动。
- 队列仅负责启动下一分集、记录关联运行和汇总状态，节点与镜头调度仍交给现有 Runtime。
- 当前项失败、遇到未知外部提交或需要处理时，默认停止派发后续项；成功后自动推进。
- 暂停派发与取消当前制作分别操作。重启通过关联运行和队列记录恢复，不能仅凭界面状态判断是否完成。
- 分集编号冲突、活动项去重及状态转换使用事务和必要的唯一约束；供应商并发继续复用现有限流。

在“我的项目”内增加作品分组和分集列表，复用制作记录查看实际运行。首版的单项目备份保留分集来源信息，导入生成独立副本；加入作品时重新校验编号。整部作品的打包迁移作为后续范围。

主要改动入口：新增作品与队列契约、Runtime 领域模块、数据库迁移与读取模型、项目列表、制作记录和项目备份。

验收条件：批量创建具备原子性；重复请求不会重复建集或启动；失败后保留成功分集；暂停后不派发新项；重启关联原运行；项目修订变化可见；独立项目继续正常工作。

### P4 按实际需求扩展素材与交付

| 能力 | 最小实验 | 进入正式开发的条件 |
| --- | --- | --- |
| 场景与道具参考 | 将项目内文字对象扩展为有类型的参考素材，复用角色参考的校验与协议适配模式 | 样例证明文字连续性不足，且目标模型支持所需图片数量与用途 |
| 多宫格素材 | 先提供现有素材的网格预览与确定性切图，再考虑调用模型生成源图 | 切片、源图哈希、裁剪坐标及镜头绑定可追溯；人工检查构图和清晰度符合需求 |
| 图片局部编辑 | 通过现有镜头候选生成新的图片版本 | 所选协议经过验证，版本不会覆盖当前采用的素材 |
| 剪映或其他剪辑工程 | 从现有时间线制作最小工程导出样例 | 先检索并核实独立导出库的许可证、维护状态、目标软件版本及双平台导入结果，再决定依赖 |
| 模型替换与容错 | 先提供明确的替代模型建议与新运行操作 | 具备可分类故障、能力与价格约束；已提交任务继续使用原回执，不因超时自动换模型重提 |
| 对话修改节点 | 将自然语言建议转换为可审阅的项目或节点修改 | 复用现有 Deep Agents、编辑命令和修订保护，能准确预览和撤销实际变更 |

多宫格切图和工程导出先复用现有 Canvas、FFmpeg 与时间线能力。节约费用、提升一致性等收益需通过样例实测后再作结论。

## 数据与兼容性要求

| 边界 | 实施要求 |
| --- | --- |
| 公共契约 | 先定义可选创作上下文与受控引用，再同步 Runtime、客户端、编辑命令和测试；场景资产与现有 `SceneTemplate` 图形模板保持独立语义 |
| 输入验证 | 模型响应先解析与收窄；真实角色及素材 ID 由系统白名单映射，运行前验证角色状态、素材哈希和协议限制 |
| 运行快照 | 冻结项目创作对象、角色池及版本；旧运行沿用其已记录上下文，不从当前角色库补造历史 |
