# 短剧制作与视听资产

「短剧工作室」是唯一制作入口，合并原项目页与短剧作品页。作品负责组织分集；每个分集复用现有编辑、撤销与重做、持久化执行及导出能力。新工作区为空，不再自动创建科普示例。旧通用创建弹窗与项目页已移除，底层 `ProjectDocument` 作为分集编辑和执行容器。

## 上传剧本与制作剧本

首页的「上传剧本」支持本地 TXT、Markdown、DOCX、含文本的 PDF，以及直接粘贴正文。「读取文件」只读取和预览文字，不保存作品、不调用模型；检查正文后点击「创建短剧」，原子保存作品与第一集。文本最多 30000 字符，超长明确拒绝，不截断。DOCX 只读取主文档的可见文字，不打开嵌入文件和外部链接；图片扫描件须先转换为文字。文件上限 10 MB，PDF 沿用最多 80 页的提取限制，DOCX 主文档解压后最多 2 MB。

「制作剧本」从创意、选题和故事设定开始，同样先创建作品和第一集，不自动发起付费生成。分集工作台的「分集剧本」可手写、上传、选择文本模型生成草稿。草稿在后台独立持久执行，关闭和重开可查看；显式「应用到本集剧本」后才写入正文。正文只保存在 `originalText`，不把生成的分镜 JSON 当作剧本。保存和应用都沿用修订保护，剧本编辑与应用支持撤销、重做。

新分集默认使用「短剧制作」流程，在原四个阶段内依次执行剧本正文、简报、风格、分镜、参考素材、视频镜头、剪辑准备、导出八项任务。制作时读取已保存剧本，不自动重写；AI 草稿由用户单独启动并应用。分镜生成使用已保存正文，剧本与镜头分镜分别编辑。

接口为 `dramaStudio.create`、`dramaScript.read`，草稿复用 `planning.prefill.start`、`node.result`、`node.apply`。`project.create` 的内部快捷创建也会建立作品与首集，统一采用短剧流程。

## 画风、选题库与内置 Skill

内置 10 种原创画风，覆盖真人、二维、三维、绘本与工艺风格。选择画风后，其说明进入分集的实际视觉风格配置；分集可以覆盖视觉类型，避免继续继承冲突的画风提示。系列模板的画幅、字幕和镜头预设仍实际应用到首集。

选题库内置 14 张原创选题卡，可搜索、查看梗概和标签、多选组合，也可新建、编辑、归档和恢复自己的选题。选题描述进入新分集的创作要求；之后修改选题库，不追改已经创建的分集。作品搜索覆盖标题与故事设定。

内置 8 项创作 Skill，覆盖剧本创作、改编、人物、对白、分镜、连续性、镜头提示与剪辑。画风会建议预选相关 Skill，用户可取消；明确选定的 Skill 进入剧本、策划、分镜及剪辑任务，运行时按现有机制冻结内容与参考资源。内置目录增量补种，保留用户修改、归档和停用状态。

选题接口为 `dramaTopic.list/get/save/archive/restore`，画风目录由共享契约 `dramaStylePresets` 提供。作品保存 `topicIds`、`stylePresetId` 和显式 `skillIds`，创建分集时展开为实际配置。

## 作品与分集

从「短剧工作室」的作品列表查看分集，填写故事设定，并分别选择视觉风格和讲述方式。真人写实、动漫与风格化、混合画风都可以搭配角色对白、旁白解说或混合讲述。作品可以选择最多 50 个共享角色。

在作品中创建分集时，复制作品当时的风格、讲述方式和角色池。已有分集不随作品默认值的修改自动改变。分集可采用自己的风格与讲述方式；同一作品的集数必须唯一，移入项目回收站的分集仍占用原集数。作品归档后不能创建新集，已有分集仍可编辑，恢复作品后可继续创建。

作品通过 `dramaWork.list/get/save/archive/restore/episodes` 访问。作品使用独立的 `drama-work` 文档，分集关联使用 `ProjectDocument.drama`。该结构与历史 `episode`、`episodeSource` 和退役的生产队列分开保存，不重新派发旧排队项。

## 场次、镜头与台词

在分集工作台打开「场次与对白」，编辑场次名称、地点、时间和描述，将镜头关联到场次。镜头继续使用稳定 ID、时长、画面及素材绑定；其 `drama` 字段保存场次、人物形象和按顺序排列的台词。

每句台词有独立 ID、类型、正文，以及可选音色、表演情绪与句后停顿。对白需要说话角色；旁白可不选角色，也可以指定角色旁白。画外说话角色参与声音与角色资料收集，不自动作为画面人物发送参考图。角色的形象绑定用于明确该镜头的服装、妆造和状态。

编辑通过现有项目会话保存，支持撤销、重做、草稿恢复和修订冲突保护。存在引用的场次或形象不能直接移除；调整引用后再移除。不同镜头的台词 ID 不能重复。保存会校验场次、角色、形象与音色是否存在。

结构化台词不为空时，生成提示以这些对白和旁白为准，旧 `narration` 保留兼容，不重复朗读。现有文字生成输入包括已保存的场次与台词上下文，输出仍遵守原有分镜契约，不由模型创建公共角色或音色 ID。生成后改变短剧绑定、相关场次、音色资料、画风或讲述方式，会阻止旧候选覆盖当前内容。

## 角色形象与音色

「素材库 → 角色」保留原角色资料与最多四张基础参考图，增加最多 50 个角色形象。每个形象有稳定 ID、名称、描述及最多四张公共参考图。需要发送角色参考图时，使用该镜头所选形象的图片；没有形象图片时回退到角色基础参考图。形象变化会影响参考图分组，其他形象的图片不会混入该镜头。生成首帧、上一镜尾帧及已有镜头画面仍遵循现有参考画面优先级和模型能力限制。

「素材库 → 音色」管理名称、声音描述、语言、可选服务音色标识及最多三份公共参考音频。参考音频为非空 WAV／MP3，每份不超过 15 MB。角色可以设置默认音色，单句可以另选音色。音色支持归档、恢复与删除；角色或项目仍使用时不能归档或删除。形象图片和音色音频受到素材占用保护。

本阶段提供音色资料、音频样本、角色及逐句绑定，以及生成提示中的声音说明。服务音色标识是资料字段，不会自动调用专用 TTS、克隆音色或口型服务。模型请求中的参考音频仍来自「制作设置 → 模型与素材」；音色库样本不会自动作为某位说话人的音频参数提交。

## 快照、备份与兼容

工作区版本 29 为新结构建立分集唯一索引和轻量摘要，并沿用升级前数据库备份。旧项目与旧运行快照原样保留；旧客户端不能打开新版本工作区。

运行冻结角色的全部形象、所选音色及其参考素材。恢复沿用冻结资料；修改库资料不会改写已启动任务。制作前检查和素材恢复覆盖形象图及音色音频。列表摘要只保留分集关联、画风与讲述方式，不展开场次和台词。

包含短剧结构、形象或音色能力的项目备份使用格式 10，保存项目、角色形象、音色、所属作品和所需素材。素材使用相对路径。备份是当前分集的完整资料，不代表整部作品的所有分集，也不增加备份导入或整剧队列功能。

## 分阶段验证

1. 契约：旧数据兼容、画风与讲述方式组合、稳定 ID 和引用关系。
2. Runtime：真实 SQLite 迁移、作品与分集读写、重启、修订冲突、引用保护、冻结和备份。
3. 编辑与媒体：场次和台词撤销／重做、选中形象图片实发、画外声隔离、结构化台词编译、过期候选拒绝。
4. 界面：作品到分集、角色形象与音色、场次和对白保存重开；代表性桌面尺寸和明暗主题。

以上验证使用隔离工作区和本地夹具，不自动发起付费生成。真实服务的人物一致性、音色效果及口型质量需要后续单独验收。

Windows 原生自动化运行真实 Electron 应用包、Node 执行器和媒体处理；文件、目录、保存对话框的返回值以及系统「显示文件」调用使用受控替代，操作系统界面仍需人工验收。当前环境未执行 macOS 实包验证。

## 参考与实现边界

技能分工参考 MIT 项目 [Drama Skills](https://github.com/zenstory-ai/drama-skills)和 [Short Drama Skills](https://github.com/YvonneMovingon/short-drama-skills)的公开结构；执行复用本项目 Runtime，不引入其外部脚本。当前逐集创作和制作，不提供自动拆整部长篇为多集、批量付费生产、转绘或托管选题市场。
