# 外部服务与性能验收

桌面自动验收、真实供应商联调、长时播放及人工桌面操作分别保存证据。本文描述当前 Electron 实现的验收方法；版本以仓库配置为准，结果必须与实际源码提交、环境和报告绑定。

## 证据范围

| 范围 | 自动化覆盖 | 独立验收内容 |
| --- | --- | --- |
| 本地协议与恢复 | 真实本地 HTTP 服务、活动／应用回执、取消、未知提交保护和三比例编码 | 实际供应商的模型可用性、限流、远端取消、任务查询及账单 |
| 桌面与安装 | 三平台真实 Electron、系统凭据、媒体协议、包外 PDF、原生恢复、安装覆盖与默认数据保留 | 系统选择器／Finder／Explorer 的实际鼠标交互、交互式卸载与人工观片 |
| 媒体性能 | 真实解码、可见缩略图、资源上限、单源与多源测量工具 | 物理 GPU／驱动、窗口进程内存和对应设备上的长时结果 |
| 分发 | 构建、组件来源、许可、包与安装记录摘要 | Developer ID／Windows 签名、公证和更新分发配置 |

供应商配置和型号列表不能证明具备某种输出能力。文本、参考图片和视频按各自角色验收，视频下载后必须探测到真实画面与音轨；缺少服务或环境时保留未验收状态。

## 真实模型成片

`scripts/real-service-smoke.ts` 复用生产 Runtime、活动回执、文本／图片／视频适配器和批量导出，不启动替代模型服务。它只在新建的验收输出目录内写工作区，不读取日常项目或系统凭据库。

配置文件由执行人放在仓库之外，包含 `title`、`brief` 和 `roles`。角色为 `text`、`image`、`video`；每项包含 `model`（与应用模型配置相同的协议、地址、型号、能力及参数）和可选 `secretEnv`（凭据环境变量名）。例如一个角色的配置如下，其余两项按实际服务补齐：

```json
{
  "roles": {
    "text": {
      "secretEnv": "VQ_TEXT_SECRET",
      "model": {
        "provider": "openai-compatible",
        "connectionType": "text",
        "baseUrl": "https://example.invalid/v1",
        "model": "YOUR_TEXT_MODEL_ID",
        "capabilities": ["text"]
      }
    }
  }
}
```

示例只解释结构，不是完整可运行配置。声音要求、视频时长和图片尺寸等参数应按所接服务填写。视频生成默认同时请求声音，下载后校验真实画面与音轨。脚本使用生产契约校验，不能通过在配置中内嵌 API Key 或认证头绕过凭据传递。声明的凭据环境变量为空时，执行会在提交前停止。

先检查配置，仅报告地址、能力与凭据是否可用：

```powershell
pnpm exec tsx scripts/real-service-smoke.ts --config "../validation/services.json"
```

确认服务、计费和输出位置后显式执行：

```powershell
pnpm exec tsx scripts/real-service-smoke.ts --config "../validation/services.json" --execute --output "../validation/service-run-001"
```

首次执行的输出目录必须不存在，其父目录应已创建。工具依次执行简报、风格、分镜、参考图、视频和本地剪辑准备，逐阶段确认并应用实际产物。三个镜头约三十秒，字幕默认关闭，随后导出横屏、竖屏和方形 MP4。预计三次文本调用、每镜头一次图片和一次视频生成；服务轮询、供应商切分及实际计费以服务端为准，此数量不是账单上限。

`evidence.json` 记录配置摘要、实际运行 ID、阶段状态、活动计数、批次、输出视频摘要和探测结果。状态 `passed` 仅表示上述技术检查通过；仍需人工检查科学表述、画面、声音、字幕与引用。凭据只保存在进程内存，失败信息会按已配置的秘密值脱敏。

需要在指定阶段停止验收时，可追加 `--stop-after script`，也支持 `brief`、`style`、`assets`、`video` 或 `animation`。工具在该阶段结果保存并应用后记录 `paused`，不提交后续模型工作；移除该选项并用同目录 `--resume` 继续。常规制作自动接续；技术验收不会自动把资料或事实主张标记为已核验。

失败或中断时保留原工作区及回执。显式追加 `--resume`，继续同一目录、配置和运行：

```powershell
pnpm exec tsx scripts/real-service-smoke.ts --config "../validation/services.json" --execute --resume --output "../validation/service-run-001"
```

恢复会分页核对已经提交的阶段运行，丢失开始回执时不创建另一运行；应用使用稳定的 `applicationId` 与原修订，同事务回执防止丢失应用结果后重复写入。已完成的阶段直接保留，导出继续同一批次并保留成功项。运行对应的凭据引用只从相同配置声明的环境变量重新绑定，模型连接或已确认项目有后续修改时停止推进。

外部提交结果未知时，`--resume` 仍停下等待核对，不自动再次 POST；可通过应用打开该隔离工作区，核对服务端任务和原回执后再继续。明确失败阶段的 `--resume` 是用户请求对原运行重试，并不证明服务端恰好一次计费。不要把新建另一验收目录视为原任务恢复。

验收前还需按真实服务记录超时、限流、取消、已有远端任务查询恢复和用量。当前本地 HTTP 协议测试覆盖这些分支的实现；真实供应商的相同行为必须保留单独证据。

工具自身的端到端回归可用 `pnpm exec tsx scripts/check-real-service-cli.ts "../validation/cli-fixture-001"` 单独运行。它使用本地 HTTP 边界和真实 FFmpeg 媒体，先停在分镜完成，再模拟应用回执丢失后恢复原运行，检查九次逻辑提交、文本步骤不重复和三种真实有声 MP4；结果明确标记 `cloudServicesVerified: false`。这项回归不能计入真实供应商联调通过。

## 多独立媒体与长时播放

`media-performance.spec.ts` 使用单个真实源测量 50／200 镜头。`media-soak.spec.ts` 使用十二个独立编码、不同 SHA-256 的 1080p H.264 文件，组成 200 镜头，覆盖连续源替换以及离屏缩略图回收。

该测量只在显式设置时注册，不增加默认回归中的跳过项。先运行短测验证环境，再执行五分钟验收；两者证据不可混称：

```powershell
$env:VIDEO_QUICKLY_SOAK_SECONDS = "15"
pnpm test:e2e tests/e2e/media-soak.spec.ts --workers=1
$env:VIDEO_QUICKLY_SOAK_SECONDS = "300"
pnpm test:e2e tests/e2e/media-soak.spec.ts --workers=1
Remove-Item Env:VIDEO_QUICKLY_SOAK_SECONDS
```

环境变量接受 15–300 的整数。测量关闭 trace，避免每帧录制改变被测负载；普通功能回归仍保留 trace 和像素断言。输出为 Playwright 产物目录中的 `independent-media-soak.json`，包含真实文件数量／不同哈希数量、机器与浏览器、播放时间、逐段解码／掉帧计数、JS 堆、创建的媒体播放器、最大活跃视频元素及所有控制台／媒体错误。混音准备和轮询的真实任务状态也保留，等待失败时可区分排队与处理失败。

每个源使用不同背景和真实运动图案。采样通过实际视频帧回调记录呈现帧与媒体时间，并比较主 Canvas 和当前原生解码源像素；实际编码／颜色管理后的源作为参考，不把名义 RGB 当作 H.264 解码真值。五分钟运行要求全部十二个独立源都被呈现，且各源运动区域在 Canvas 中发生变化；十五秒短测至少覆盖多个源。持续播放时还检查节目时间推进和带源视频元素不超过主预览加两路取帧的上限；结束后定位第 200 镜头验证回收与重新读取。

每次观测只挂接约 300 毫秒的视频帧回调，观测之间间隔约 650 毫秒，另有 CDP 与页面等待开销；挂接前及源切换期间的帧不在该窗口计数中。源切换还会结束旧视频元素的寿命，因此累计回调数不能除以整段播放时长来计算 FPS，也不能据此宣称固定帧率。原始每个窗口的媒体时间与逐源样本保留在证据文件中。

Chromium 堆不等于进程私有内存或 GPU 显存；该工具明确记录 `nativeGpuMeasured: false`。Electron 原生窗口及物理 GPU 需在对应 Windows／Mac 设备采集。列表虚拟化、代理媒体等实现应由这些测量中的实际瓶颈决定。

## 平台联合验收

按 [Windows 自动安装与人工矩阵](windows-verification.md)及 [Mac 双架构验收](macos-verification.md)执行。`install-smoke.ps1`、`installed-runtime-smoke.mjs` 与 `install-macos-smoke.mjs` 用于全新隔离 CI 账号，执行前拒绝已有日常工作区，不应在个人数据环境绕过保护。

每个交付提交关联自身的类型、Runtime、浏览器、实际媒体、原生与安装报告。核对 Actions 目标提交和实际 checkout 的合并父链，再比较归档、清单与实际安装包／ZIP 的 SHA-256。数据库、存在的 WAL 和媒体比较存在性、长度与摘要；若 WAL 前后均不存在，应如实记录，不声称已比较 WAL 内容。

实际桌面还需补充系统路径选择和取消、目录定位、交互式卸载、系统播放器观片以及物理 GPU／驱动采样。系统凭据的自动验收使用随机独立测试引用，结束后清理，不读取日常密钥。自动化提供对话框的用户选择结果不等于人工点击系统界面。

## 完成判定

| 范围 | 必须保留的证据 |
| --- | --- |
| 当前桌面交付 | 对应源码的三平台完整 CI、实际包、原生与安装报告、组件来源许可、包与安装记录摘要 |
| 真实模型闭环 | 已配置服务的实际运行／回执、参考图与视频、三比例音视频探测、人工成片审阅及供应商账单核对 |
| 多独立源长时播放 | 300 秒配置实际完成的测量文件、十二个不同文件哈希、连续播放与回收断言；15 秒环境短测不替代五分钟测量 |
| 原生人工与性能 | 对应 Windows／Mac 设备和架构、操作路径、GPU／驱动与窗口采样；虚拟 CI、Chromium 堆或其他平台测量不能代替 |

报告中的 `passed` 仅对应其实际覆盖范围。工具和协议测试通过证明方法与实现可用，不能自动升级为供应商、物理设备或发布分发已验收。
