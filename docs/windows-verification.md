# Windows 交付与恢复验收

## 自动检查

`Windows verification` 工作流在隔离的 `windows-2025` 运行器中执行锁定依赖安装、类型检查、自动测试、浏览器流程、四组实际媒体导出、Tauri 构建和原生执行组件测试。Node 版本见 `.node-version`，Rust 版本见 `rust-toolchain.toml`，pnpm 版本见根 `package.json`。

媒体组件由 `pnpm prepare:media` 下载和校验，版本、固定下载地址、SHA-256 与源码地址见 `scripts/media-manifest.json`。更换构建时必须审核来源、摘要与许可。脚本不会自动采用其他版本；固定下载失效时需要审核后更新清单。

安装包只保存为工作流产物，不自动发布 Release。交付清单位于 `.generated/release/manifest.json`，包含提交、工具版本、前端和执行组件摘要，以及实际测试结果。测试失败时保留浏览器日志和跟踪；不生成成功交付清单。

### 本轮状态与远程验收准备

2026-10-30 的本轮开发环境为 macOS arm64。提交前已完成本地检查；包含本轮全部变更的 Windows CI／安装结果以推送后对应提交的 Actions 为准，不能沿用上一提交的状态。完整本地 HTTP CLI 自测已导出三比例各 30 秒 MP4，独立 12 源／200 镜头的 Chromium 300 秒测量也已通过；两项均不能计入 Windows 原生或真实供应商验收。详细证据和观测边界见 [真实服务与长时媒体验收](release-validation.md)。真实模型联调仍缺服务连接、适用参数及费用上限，CI 不会自动获得或调用日常模型凭据。

远程流程由 `.github/workflows/ci.yml` 定义。提交推送到 `main` 或创建 PR 会自动执行；已存在对应提交的运行时直接检查该次结果。需要手动补跑时，先将审核后的变更提交并推送到验收分支，再按实际分支触发；未提交的本地改动不会被远程运行包含。以下为手动补跑的准备命令：

```powershell
$taskBranch = "<已推送的验收分支>"
$taskCommit = git rev-parse HEAD
gh workflow run ci.yml --ref $taskBranch
gh run list --workflow ci.yml --branch $taskBranch --event workflow_dispatch --limit 5 --json databaseId,headSha,status,conclusion,url
```

核对返回运行的 `headSha` 与 `$taskCommit` 完全一致，再保存运行 ID；同一分支再次触发会按现有并发规则取消旧运行，因此不要并发补跑。等待并归档该次真实结果：

```powershell
gh run watch <运行ID> --exit-status
gh run download <运行ID> --name "video-quickly-windows-x64-$taskCommit" --dir "<新的验收归档目录>"
```

核对该提交的自动测试／浏览器报告、四组实际媒体导出、原生测试、安装覆盖升级、默认卸载保留数据及交付清单。失败时保留失败报告，不能沿用历史提交的成功状态。CI 未安排真实供应商、300 秒专项或原生 GPU 采样；后三项需按验收文档显式执行，并补齐下方人工矩阵。

## 隔离安装验收

`scripts/install-smoke.ps1` 会修改安装注册项和隔离账号的应用数据，因此只允许在 GitHub Actions 的 Windows 环境运行，并且拒绝已有项目数据的账号。它验证：

1. 带中文和空格路径的静默安装，以及随附执行组件和 FFmpeg。
2. 创建实际待审任务，并将数据库转换成当前已交付的无版本 Schema 基线。
3. 覆盖安装、启动原生客户端并检查数据库迁移完成。
4. 从安装目录运行执行组件，继续原待审任务；已完成活动保持一条。
5. 实际导出一个短 MP4，再次启动和退出客户端；检查执行子进程退出。
6. 静默卸载并确认项目数据库保留。

同版本覆盖安装验证安装与数据迁移路径；不同版本之间的升级仍需保留上一版本安装包单独验证。自动化结果记录在 `.generated/install-smoke.json`。

## 数据库迁移与恢复

应用启动时先检查 `PRAGMA user_version`。新工作区顺序初始化 Schema；旧工作区先通过 SQLite 创建包含已提交 WAL 数据的独立快照，刷入磁盘后再在一个事务内执行所有待迁移项。版本、迁移记录和结构一并提交；失败时事务回滚。高于客户端支持版本的数据库会被拒绝打开。

当前 Schema 版本为 7。版本 6 在原有音乐、旁白和字幕来源引用之外，保护剪辑来源快照中的原始素材；摘要通过同一事务内的确定性函数投影剪后首帧，不传输完整字幕、来源或剪辑计划。版本 5 的项目默认字幕样式保持同步，完整项目、运行与检查点不改写。版本 7 的能力边界见下文；安装验收脚本已检查当前版本，Windows 原生验收仍须在隔离 Windows 环境实际执行。

含剪辑计划或显式声音处理的项目备份使用格式 2，旧客户端会明确拒绝；纯旧格式项目仍可导出格式 1，本版本兼容导入两者。完整备份保留原录音、原视频和字幕来源，以便恢复原始窗口。试听混音与电平属于可重建派生缓存，不写入项目、执行记录或费用；重启后的未完成试听需用户重新准备。

视频原声配置使用声音处理版本 2，读取它需要支持该版本的客户端；既有旁白设置继续使用版本 1。原声默认关闭，不向旧项目自动补写。项目备份格式 2 保留原声配置及对应视频引用；分割和非连续剪辑后恢复到新项目时，原视频编号和冻结来源引用一起重建。

关键帧、固定版本子流程及并发设置引入后，工作区升级到 Schema 7，以阻止旧客户端打开后静默移除新字段。升级仍先备份，再事务提交；不重写原项目、模型凭据引用或既有检查点。包含这些能力的项目备份使用格式 3，继续兼容导入格式 1／2；旧格式文件携带新增能力时拒绝导入。验收必须同时覆盖实际 Schema 6 升级、迁移前快照、旧客户端拒绝，以及备份恢复后的固定版本和关键帧内容。

迁移前快照保存在工作区的 `database-backups/`。它覆盖项目文档、运行事件、活动回执和 LangGraph 检查点；系统凭据及磁盘媒体仍由原存储位置管理。快照不会自动删除。

在源码工作区执行以下命令，可将快照恢复至一个不存在的新目录，保留当前工作区：

```powershell
node scripts/recover-database.mjs --backup "D:\备份\workspace-v4-to-v5-快照.sqlite" --destination "D:\恢复的工作区"
```

恢复工具先检查快照完整性，拒绝已有目标目录和仍依赖 WAL 的数据库文件。可以使用 `pnpm start:runtime -- --data-dir "D:\恢复的工作区"` 检查恢复结果。媒体仍引用原路径；整项目迁移使用已有的项目备份与导入能力。替换桌面工作区前关闭应用并另存原数据目录，不能在运行期间覆盖数据库。

## 执行组件重连规则

原生桥接以一次执行组件启动为一个代次，串行处理重连请求，等待启动握手后才接收业务请求。失联时结束该代次的未完成请求；替换前停止原进程组，旧代次事件不会覆盖新连接状态。

重新连接只刷新持久化状态。创建项目、生成素材、导出及其他已提交操作不会由桥接自动重试。已经存在的运行继续遵守 LangGraph 检查点和外部调用回执的恢复规则；提交结果不明的活动仍需核对。


## 浏览器构建产物验收

`pnpm test:e2e` 在隔离目录中先构建 `browser-test` 前端，再通过 Vite 的预览服务运行相同的真实 TypeScript 执行层、SQLite、媒体组件和临时模型凭据库。构建文件写入 `apps/desktop/.generated/browser-preview`；不会替换桌面打包使用的 `dist`。手动启动 `pnpm dev:e2e` 时，默认数据目录为 `.data/browser-preview`，显式设置的 `VIDEO_QUICKLY_DATA_DIR` 优先。

此模式下前端使用生产编译与分块加载，通过经过公共事件 Schema 校验的同源 EventSource 接收实际工作区通知。连接恢复后只重新读取状态，业务请求不重试。测试继续覆盖真实生成夹具、人工审阅、保存失败、撤销、导出以及原有像素／时间断言；通知竞态用 CDP 观察实际 SSE 或开发 WebSocket 事件，并执行同一个通知防抖计时器。

`pnpm dev` 保持源码开发与 HMR；正式桌面构建继续使用原生 IPC。浏览器测试模式是显式构建选项，正式包不启用浏览器 RPC 或事件桥接。桥接复用 [Vite 的 configurePreviewServer](https://vite.dev/guide/api-plugin.html#configurepreviewserver)，没有增加新的服务框架或依赖。
