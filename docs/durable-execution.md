# 持久化执行契约

## 身份与快照

每份运行固定项目修订、工作流版本、模型配置和 Skill 版本。活动身份属于该运行与节点；同一活动的恢复沿用操作身份，主动重新生成创建新身份。输入摘要用于检测恢复时的配置漂移。

步骤状态、分支与人工中断由 LangGraph 原生检查点管理。应用的活动记录只负责模型、工具和媒体请求边界，不另行调度工作流。图恢复可能重新进入节点，因此外部操作必须复用已保存结果或核对原请求；UI 展示事件不能作为完成依据。

Deep Agents 使用同一套 SQLite 持久检查点保存内部模型与工具循环。每次模型或工具调用单独保存结果；媒体步骤的各镜头分别保存提交、远端任务、下载和文件完成回执。

## 固定版本子流程与镜头并行

子流程模板每次保存创建不可变版本。项目内保存所引用版本及传递依赖的完整副本；后续模板编辑、归档和备份恢复不会改写已有运行。输入声明明确 JSON 类型，支持字面值、上游产物路径和嵌套输入透传；输出只允许引用声明节点的实际产物路径。展开后的步骤最多 1000 个、嵌套最多 8 层，超限在创建运行快照前拒绝。

子流程节点身份使用 `父节点/subflow/编码后的子节点`，每次调用有独立 SQLite 图线程 `运行:subflow:节点`。审阅中断逐层传给父图，恢复时只重放已经保存的对应决定。步骤详情按各自原生检查点读取状态，并保存参数代入后的实际节点定义及执行项目上下文，避免应用产物时重新解释模板。

显式启用镜头并行的新运行使用处理器版本 3；旧版本 1、2 保留原执行路径。模型媒体步骤使用独立 `运行:media:节点` 原生 LangGraph `Send` 扇出和汇合，每波派发不超过冻结的镜头并发数；原生 `join` 保存本波结果后只派发剩余镜头。每个任务只携带稳定镜头身份，成功兄弟结果由 SQLite 检查点及 pending writes 保留。失败恢复只推进缺少结果的镜头；适配器仍通过原操作身份和镜头回执核对任务、恢复下载并阻止未知提交重复 POST。原生图完成后再次流式校验素材大小和 SHA-256，再提交父活动。按波派发规避当前 LangGraph 运行器在大量排队 Send 和单并发时可能提前结束的问题，测试覆盖 64 镜头单并发及失败后尚未启动的任务。

项目镜头并发限制为 1–8，同一运行进程中的所有项目共用按模型连接限流。取消会停止排队任务、传递中止信号并等待实际在途回调释放资源；取消后的运行保持终态，恢复失败运行才继续未完成镜头。此限流不声称跨进程或跨机器协调远端服务。

包含子流程、并行配置或关键帧的新备份使用格式 3；格式 1、2 保持可导入，但不能伪装携带新能力。数据库版本 7 阻止旧客户端打开后静默丢弃这些字段。

## 外部操作

1. 在操作前记录准备状态与操作身份。
2. 支持服务端幂等键时，同一操作的重试保持相同键。
3. 在查询前保存返回的远端任务编号。
4. 查询和下载恢复使用原任务，不创建替代生成任务。
5. 无幂等机制且提交结果不明确时，转为待核对，不能自动重复提交。
6. 完整结果校验后，记录活动完成并允许图推进。

服务商查询、幂等和取消能力决定外部操作的恢复边界。本地进程退出与远端取消分别记录。

## 审阅、重放与取消

审阅节点只保存审阅请求和决定；生成等副作用由后续独立活动执行。用户修改审阅对象时必须创建新修订，旧决定不能被应用到新对象。

重放检查只读取历史记录，不提交模型、工具或渲染操作。继续运行恢复旧快照；修改后重做创建关联的新运行。

“制作记录 → 查看步骤”读取冻结流程和原生 SQLite 检查点，区分待执行、已完成、条件分支未经过、人工审阅及历史未记录。完成活动的回执不等于编排检查点已经推进；产物先保存、检查点尚未推进时，详情保持这个差异。没有冻结流程的旧运行只展示已有活动和日志，不以当前项目流程补造历史。

步骤输入来自 `node-project` 中步骤实际开始时的上下文，包含上游已经生成的项目内容。新活动额外保存输入摘要和执行时的提示词；已完成或已提交的旧回执在恢复时不补造最终提示词。这是执行上下文记录，不代表 HTTP 请求的逐字副本。输入和产物按所选步骤读取，历史版本先分页加载元数据，再读取明确选择的版本。

查看与比较不会调用生成器。应用产物先进入项目编辑会话，沿用当前修订、冻结项目基线、角色和素材校验，产生可撤销编辑；生成后已有人工修改时保留原内容并拒绝覆盖。画面、旁白及视频使用所选步骤的实际输入与产物计算对应状态，不读取整次运行最后的 `run-project` 来替代较早步骤。素材在应用前流式核对大小与哈希，异步读取结束后再次核对项目修订和素材身份。

自动化调用 `node.apply` 可提供稳定 `applicationId`。相同标识及运行、节点、修订的重试返回第一次提交结果，回执与项目写入在同一事务中保存；标识复用于不同参数会拒绝。确认丢失后的重试不会覆盖第一次应用之后的人工编辑。

诊断由用户明确导出为本地 `.json.gz`，包含冻结快照、检查点摘要、步骤上下文／产物及捕获上界以内的全部活动和事件。导出按记录流式压缩，记录开始与完成时间；活动制作期间不声称它是跨所有表的原子快照。已知模型密钥、敏感字段、URL 凭据和签名参数会隐藏，媒体数据保留素材引用。失败只清理由这次导出创建的未完成文件。

本地取消信号必须传递到正在等待的操作及子进程。原生层负责清理附属进程；远端任务取消不成功时保留可查询编号及状态。

## 文件与数据库

产物先写入临时路径，经文件探测和校验后原子重命名。完成活动、资产版本和相关业务状态在同一应用事务中登记。检查点尚未推进时，恢复依照已提交的活动结果返回，不重做外部操作。

一次工作区只由一个执行进程负责数据库写入。同一项目同时只能有一份活动运行。数据库使用 WAL、外键检查和同步持久化；此保证属于本机实例范围。

## 验证场景

- 结果已保存、图检查点尚未推进时退出进程。
- 外部提交结果不明确时退出并重新继续。
- 已保存远端任务编号后中断轮询和下载。
- 人工审阅等待期间重启。
- 重新进入节点时复用完成结果。
- 重放过程中验证外部调用次数为零。
- 旧运行快照与新项目修订保持隔离。
- 文件缺失、损坏或只存在临时输出时不展示为完成。
- 双层子流程逐次审阅跨重启，固定版本备份恢复及真实参数化 ASR 应用。
- 镜头原生 pending write、已知远端任务、未知提交和待下载阶段实际 SIGKILL 后重启。
