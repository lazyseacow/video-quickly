# 持久化执行契约

## 身份与快照

默认视频流程将项目统一文本、视频与可选图片模型配置保存到 `workflow.production`。任务通过显式绑定继承统一选择，高级设置中的独立模型优先；创建运行前解析为具体模型和任务参数，再写入冻结快照。运行中的待用配置包含模型选择、任务设置和项目创作参数，沿用基线冲突检测，下次制作才应用。

参考素材准备允许直接文生视频、使用已有参考图或先生成参考图。视频请求传递台词、声音要求和同步音频参数；下载后探测真实视频、音轨和时长。缺少音轨时保留下载文件和原任务回执并报告原因，继续操作恢复原下载。有效视频自动启用原声，清理本镜头的独立旁白关联，避免重复混音，按实际视频时长安排新镜头。剪辑准备和成片渲染复用本地媒体链路。

`subtitleMode` 默认 `off`，预览、首帧投影和导出均遵守该设置；`script` 使用分镜文字及预估时间。制作流程必须包含 `production` 配置；模型连接必须声明文本、图片或视频类型。项目备份统一使用格式 4，其他格式拒绝导入。

每份运行固定项目修订、工作流版本及阶段元数据、模型配置和 Skill 版本。活动身份属于该运行与节点；同一活动的恢复沿用操作身份，主动重新生成创建新身份。输入摘要用于检测恢复时的配置漂移。

阶段用于界面分组和集中配置，实际调度由节点与依赖决定。工作台展示完整阶段进度，局部执行范围由本次运行冻结的节点集合决定；`run.inspect` 返回该集合内的真实步骤状态。未执行任务在完整进度中保持待执行，查看其他阶段只读取详情或打开配置。展示分组与执行快照的对应关系见[四阶段进度契约](workspace-editing.md#制作指引与四阶段进度)。

步骤状态、分支与恢复由 LangGraph 原生检查点管理。制作任务和子流程自动推进。应用的活动记录只负责模型、工具和媒体请求边界，不另行调度工作流。图恢复可能重新进入节点，因此外部操作必须复用已保存结果或核对原请求；UI 展示事件不能作为完成依据。

Deep Agents 使用同一套 SQLite 持久检查点保存内部模型与工具循环。每次模型或工具调用单独保存结果；媒体步骤的各镜头分别保存提交、远端任务、下载和文件完成回执。

## 固定版本子流程与镜头并行

子流程模板每次保存创建不可变版本。项目内保存所引用版本及传递依赖的完整副本；后续模板编辑、归档和备份恢复不会改写已有运行。输入声明明确 JSON 类型，支持字面值、上游产物路径和嵌套输入透传；输出只允许引用声明节点的实际产物路径。展开后的步骤最多 1000 个、嵌套最多 8 层，超限在创建运行快照前拒绝。

子流程节点身份使用 `父节点/subflow/编码后的子节点`，每次调用有独立 SQLite 图线程 `运行:subflow:节点`。子流程自动执行并汇总声明的输出。步骤详情按各自原生检查点读取状态，并保存参数代入后的实际节点定义及执行项目上下文，避免应用产物时重新解释模板。

处理器按普通任务、局部执行和镜头并行保存执行快照。模型媒体步骤使用独立 `运行:media:节点` 原生 LangGraph `Send` 扇出和汇合，每波派发不超过冻结的镜头并发数；原生 `join` 保存本波结果后只派发剩余镜头。每个任务只携带稳定镜头身份，成功兄弟结果由 SQLite 检查点及 pending writes 保留。失败恢复只推进缺少结果的镜头；适配器仍通过原操作身份和镜头回执核对任务、恢复下载并阻止未知提交重复 POST。原生图完成后再次流式校验素材大小和 SHA-256，再提交父活动。按波派发规避当前 LangGraph 运行器在大量排队 Send 和单并发时可能提前结束的问题，测试覆盖 64 镜头单并发及失败后尚未启动的任务。

生产入口在原生重放前通过 `preflightActivity: validateMediaActivity` 核对同一操作的完整镜头批次；只要存在 `prepared/unknown` 回执，就先核对原提交，不启动尚未提交的兄弟镜头。直接调用媒体执行器也会检查传入的整批项目。嵌入 Runtime 的自定义宿主应同时接入该预检；不透明的自定义执行函数仍由宿主管理副作用边界。`submitted/download/completed` 回执不受此拦截，继续查询、下载或复用原结果。

项目镜头并发限制为 1–8，同一运行进程中的所有项目共用按模型连接限流。取消会停止排队任务、传递中止信号并等待实际在途回调释放资源；取消后的运行保持终态，恢复失败运行才继续未完成镜头。此限流不声称跨进程或跨机器协调远端服务。

子流程、并行配置、关键帧与制作设置统一写入格式 4 备份，导入后校验完整契约和素材哈希。

## 外部操作

1. 在操作前记录准备状态与操作身份。
2. 支持服务端幂等键时，同一操作的重试保持相同键。
3. 在查询前保存返回的远端任务编号。
4. 查询和下载恢复使用原任务，不创建替代生成任务。
5. 无幂等机制且提交结果不明确时，转为待核对，不能自动重复提交。
6. 完整结果校验后，记录活动完成并允许图推进。

服务商查询、幂等和取消能力决定外部操作的恢复边界。本地进程退出与远端取消分别记录。

## 自动接续、重放与取消

各步骤以实际执行时的 `run-project` 为上下文：简报、风格、分镜、参考图与视频关联依次合并。后续媒体活动接收冻结素材及本次已完成产物，文本任务同时接收依赖链上已经保存的实际输出。模型输出校验成功并原子保存后才允许继续下游；无效 JSON、镜头身份冲突、锁定镜头变化及媒体错误会停止推进。

界面通过 `run.resume` 继续中断的制作，复用已经提交的活动与媒体回执。执行图只包含调度和执行节点，不产生人工审核等待；`run.review` 不再提供。

完整多步骤制作成功后，运行上下文自动保存到项目；项目修订必须仍与启动快照相同，并在同一事务保存应用回执，恢复时不会重复应用。制作期间存在项目编辑时保留当前内容，记录冲突事件，步骤产物仍可查看。单步执行、显式局部范围、镜头候选、资料提取与批量导出保持各自的应用或输出契约。

重放检查只读取历史记录，不提交模型、工具或渲染操作。继续运行恢复旧快照；修改后重做创建关联的新运行。

“制作记录 → 查看步骤”读取冻结流程和原生 SQLite 检查点，区分待执行、已完成、条件分支未经过、历史暂停及历史未记录。完成活动的回执不等于编排检查点已经推进；产物先保存、检查点尚未推进时，详情保持这个差异。没有冻结流程的旧运行只展示已有活动和日志，不以当前项目流程补造历史。

步骤输入来自 `node-project` 中步骤实际开始时的上下文，包含上游已经生成的项目内容。新活动额外保存输入摘要和执行时的提示词；已完成或已提交的旧回执在恢复时不补造最终提示词。这是执行上下文记录，不代表 HTTP 请求的逐字副本。输入和产物按所选步骤读取，历史版本先分页加载元数据，再读取明确选择的版本。

查看与比较不会调用生成器。应用产物先进入项目编辑会话，沿用当前修订、冻结项目基线、角色和素材校验，产生可撤销编辑；生成后已有人工修改时保留原内容并拒绝覆盖。画面、旁白及视频使用所选步骤的实际输入与产物计算对应状态，不读取整次运行最后的 `run-project` 来替代较早步骤。素材在应用前流式核对大小与哈希，异步读取结束后再次核对项目修订和素材身份。

自动化调用 `node.apply` 可提供稳定 `applicationId`。相同标识及运行、节点、修订的重试返回第一次提交结果，回执与项目写入在同一事务中保存；标识复用于不同参数会拒绝。确认丢失后的重试不会覆盖第一次应用之后的人工编辑。

诊断由用户明确导出为本地 `.json.gz`，包含冻结快照、检查点摘要、步骤上下文／产物及捕获上界以内的全部活动和事件。导出按记录流式压缩，记录开始与完成时间；活动制作期间不声称它是跨所有表的原子快照。已知模型密钥、敏感字段、URL 凭据和签名参数会隐藏，媒体数据保留素材引用。失败只清理由这次导出创建的未完成文件。

本地取消信号必须传递到正在等待的操作及子进程。原生层负责清理附属进程；远端任务取消不成功时保留可查询编号及状态。

## 文件与数据库

产物先写入临时路径，经文件探测和校验后原子重命名。完成活动、资产版本和相关业务状态在同一应用事务中登记。检查点尚未推进时，恢复依照已提交的活动结果返回，不重做外部操作。

一次工作区只由一个执行进程负责数据库写入。同一项目同时只能有一份活动运行。数据库使用 WAL、外键检查和同步持久化；此保证属于本机实例范围。

## 验证场景

- 结果已保存、图检查点尚未推进时退出进程。
- 外部提交结果不明确时退出并重新继续。
- 已保存远端任务编号后中断轮询和下载。
- 历史暂停检查点重启后自动继续。
- 重新进入节点时复用完成结果。
- 重放过程中验证外部调用次数为零。
- 旧运行快照与新项目修订保持隔离。
- 文件缺失、损坏或只存在临时输出时不展示为完成。
- 双层子流程自动接续及跨重启恢复，固定版本备份恢复及真实参数化 ASR 应用。
- 镜头原生 pending write、已知远端任务、未知提交和待下载阶段实际 SIGKILL 后重启。
