# 持久化执行契约

## 身份与快照

默认视频流程将项目统一文本、视频与可选图片模型配置保存到 `workflow.production`。任务通过显式绑定继承统一选择，高级设置中的独立模型优先；创建运行前解析为具体模型和任务参数，再写入冻结快照。运行中的待用配置包含模型选择、任务设置和项目创作参数，沿用基线冲突检测，下次制作才应用。

参考素材准备允许直接文生视频、使用已有参考图或先生成参考图。视频请求传递台词、声音要求和同步音频参数；下载后探测真实视频、音轨和时长。缺少音轨时保留下载文件和原任务回执并报告原因，继续操作恢复原下载。有效视频自动启用原声，清理本镜头的独立旁白关联，避免重复混音，按实际视频时长安排新镜头。剪辑准备和成片渲染复用本地媒体链路。

`subtitleMode` 默认 `off`，预览、首帧投影和导出均遵守该设置；`script` 使用分镜文字及预估时间。制作流程必须包含 `production` 配置；模型连接必须声明文本、图片或视频类型。带分集关联或来源的项目使用格式 7 备份，提示词绑定或模板版本引用使用格式 6，创作上下文使用格式 5，其余使用格式 4；导入支持格式 4、5、6、7，并检查内容与格式一致。

项目可选的 `creativeContext` 保存最多 50 个公共角色引用、100 条人物／场景／道具文字设定及全片连续性要求。新运行冻结项目角色池与已有镜头角色的并集；文字步骤使用冻结顺序分配的 `role-N` 白名单，媒体步骤只接收实际镜头子集。新分镜通过 `characterKeys` 建立真实绑定，`entityKeys` 映射为镜头的 `creativeEntityKeys`；新文字对象随分镜结果进入 `run-project`。未知引用、重复或冲突设定在继续媒体步骤前拒绝，已有人工绑定、锁定和剪辑保护继续生效。单镜头候选不新增设定，其应用会核对镜头连续性上下文。

每份运行固定项目修订、工作流版本及阶段元数据、模型配置和 Skill 版本。活动身份属于该运行与节点；同一活动的恢复沿用操作身份，主动重新生成创建新身份。输入摘要用于检测恢复时的配置漂移。

阶段用于界面分组和集中配置，实际调度由节点与依赖决定。工作台展示模型任务的生成进度，局部执行范围由本次运行冻结的节点集合决定；`run.inspect` 返回该集合内的真实步骤状态。未执行任务在完整进度中保持待执行，查看其他阶段只读取详情或打开配置。展示分组与执行快照的对应关系见[生成进度契约](workspace-editing.md#制作指引与生成进度)。

步骤状态、分支与恢复由 LangGraph 原生检查点管理。制作任务和子流程自动推进。应用的活动记录只负责模型、工具和媒体请求边界，不另行调度工作流。图恢复可能重新进入节点，因此外部操作必须复用已保存结果或核对原请求；UI 展示事件不能作为完成依据。

Deep Agents 使用同一套 SQLite 持久检查点保存内部模型与工具循环。每次模型或工具调用单独保存结果；媒体步骤的各镜头分别保存提交、远端任务、下载和文件完成回执。

## 固定版本子流程与镜头并行

子流程模板每次保存创建不可变版本。项目内保存所引用版本及传递依赖的完整副本；后续模板编辑、归档和备份恢复不会改写已有运行。输入声明明确 JSON 类型，支持字面值、上游产物路径和嵌套输入透传；输出只允许引用声明节点的实际产物路径。展开后的步骤最多 1000 个、嵌套最多 8 层，超限在创建运行快照前拒绝。

子流程节点身份使用 `父节点/subflow/编码后的子节点`，每次调用有独立 SQLite 图线程 `运行:subflow:节点`。子流程自动执行并汇总声明的输出。步骤详情按各自原生检查点读取状态，并保存参数代入后的实际节点定义及执行项目上下文，避免应用产物时重新解释模板。

处理器按普通任务、局部执行和镜头并行保存执行快照。模型媒体步骤使用独立 `运行:media:节点` 原生 LangGraph `Send` 扇出和汇合，每波派发不超过冻结的镜头并发数；原生 `join` 保存本波结果后只派发剩余镜头。每个任务只携带稳定镜头身份，成功兄弟结果由 SQLite 检查点及 pending writes 保留。失败恢复只推进缺少结果的镜头；适配器仍通过原操作身份和镜头回执核对任务、恢复下载并阻止未知提交重复 POST。原生图完成后再次流式校验素材大小和 SHA-256，再提交父活动。按波派发规避当前 LangGraph 运行器在大量排队 Send 和单并发时可能提前结束的问题，测试覆盖 64 镜头单并发及失败后尚未启动的任务。

生产入口在原生重放前通过 `preflightActivity: validateMediaActivity` 核对同一操作的完整镜头批次；只要存在 `prepared/unknown` 回执，就先核对原提交，不启动尚未提交的兄弟镜头。直接调用媒体执行器也会检查传入的整批项目。嵌入 Runtime 的自定义宿主应同时接入该预检；不透明的自定义执行函数仍由宿主管理副作用边界。`submitted/download/completed` 回执不受此拦截，继续查询、下载或复用原结果。

素材生成 POST 收到明确拒绝的 HTTP 400/401/402/403/404/405/406/410/413/414/415/422/429 时，保存 `rejected` 回执及状态码，活动与费用记录为失败。显式重试仅为这些镜头增加提交尝试编号及幂等键后缀，已完成的兄弟镜头继续复用；查询 GET 的错误不会将已有任务改成可重新提交。断连、超时及结果不明的状态保持 `unknown`。数据库版本 19 阻止不识别此回执语义的旧客户端打开工作区；升级不会推断旧 `unknown` 记录的远端结果。

Seedream 5 参考图未显式配置尺寸时，按视频画幅将生成尺寸限制在 3,686,400–16,777,216 像素范围，例如 1920×1080 的视频生成 2560×1440 的参考图。导出配置保持原值。显式尺寸在提交前检查总像素及宽高比，错误提示包含 `size` 字段和合法范围。

项目镜头并发限制为 1–8，同一运行进程中的所有项目共用按模型连接限流。取消会停止排队任务、传递中止信号并等待实际在途回调释放资源；取消后的运行保持终态，恢复失败运行才继续未完成镜头。此限流不声称跨进程或跨机器协调远端服务。

子流程、并行配置、关键帧与制作设置写入格式 4 或 5 备份。格式 5 额外保留创作上下文及镜头设定引用；项目角色池和镜头绑定一并重映射角色 ID，引用图片保持公共素材身份，导入后校验完整契约和素材哈希。

## 外部操作

1. 在操作前记录准备状态与操作身份。
2. 支持服务端幂等键时，同一操作的重试保持相同键。
3. 在查询前保存返回的远端任务编号。
4. 查询和下载恢复使用原任务，不创建替代生成任务。
5. 无幂等机制且提交结果不明确时，转为待核对，不能自动重复提交。
6. 完整结果校验后，记录活动完成并允许图推进。

已保存任务编号后的进度查询由程序自动恢复。GET 遇到临时网络断连、连接或正文超时，以及 HTTP 408/429/500/502/503/504 时，按 1、2、4、8、16、30 秒退避，普通退避上限 30 秒；服务端的 `Retry-After`（秒数或 HTTP 日期）可延长等待。一次查询成功后连续失败计数清零，任务仍在生成时按正常间隔继续查询。鉴权／权限／任务不存在、无效 JSON 和服务端明确的任务失败不重试；生成 POST 不进入查询重试。

正常查询、重试等待及在途请求共用 `pollTimeoutSeconds` 时限，默认 30 分钟，允许范围 30 秒至 24 小时；重试不重置时限。取消会立即中止等待与请求。时限耗尽后保留已提交回执和原任务编号，后续显式恢复可开启新的查询窗口，不创建替代任务。自动重试及恢复写入结构化日志，不记录任务编号、凭据或供应商响应体。

服务商查询、幂等和取消能力决定外部操作的恢复边界。本地进程退出与远端取消分别记录。

## 自动接续、重放与取消

各步骤以实际执行时的 `run-project` 为上下文：简报、风格、分镜、参考图与视频关联依次合并。后续媒体活动接收冻结素材及本次已完成产物，文本任务同时接收依赖链上已经保存的实际输出。模型输出校验成功并原子保存后才允许继续下游；无效 JSON、镜头身份冲突、锁定镜头变化及媒体错误会停止推进。

界面通过 `run.resume` 继续中断的制作，复用已经提交的活动与媒体回执。执行图只包含调度和执行节点，不产生人工审核等待；`run.review` 不再提供。

步骤详情和阶段结果中的“重试此步骤”调用 `run.step.retry`，仅允许选择原运行当前失败的步骤。重试沿用冻结配置、该步骤实际输入、本次已完成的上游产物、活动身份与媒体回执，在原 SQLite 图线程中只执行该节点，完成后保留后续任务待执行，并提示继续剩余制作。只有全部任务完成时才标记整次制作成功并按原契约保存项目；子流程内部的失败节点同样单独重试。重试范围随运行持久保存，中断恢复不会扩大为完整流程。未知外部提交保持待核对，批量导出通过其原有恢复入口处理。

工作区版本 16 保护单步骤重试的检查点语义，升级沿用迁移前备份机制；旧客户端会拒绝打开，避免将单节点图结束误判为整次制作完成。既有运行快照、活动输入摘要和步骤产物保持原值。

分镜文本请求在提交前保存本地回执，收到返回后先持久保存原文与用量，再执行 JSON、字段和引用校验。校验失败记为 `failed`，详情显示具体字段路径、约束和可展开的原始返回（读取时隐藏敏感内容）；不会生成成功产物或标记为外部结果未知。截断输出即使能解析成 JSON 也会拒绝。尚未收到完整返回的提交仍为未知，禁止重复提交。

文本接口明确返回请求拒绝（例如 HTTP 400、401、403、422、429）时，活动和费用状态记为失败，本地回执记为 `rejected`，详情保留安全的 HTTP 状态，可显式单步重试。恢复只读取该回执，不重新发送。超时、断连、HTTP 408／409／5xx 等不确定结果仍保留未知保护。仅当接口明确拒绝程序自动添加的结构化输出参数时，移除自动格式参数并以原提示词提交一次兼容请求；此选择按本次步骤持久保存，用户显式配置的格式不被覆盖。工作区版本 18 保护拒绝回执语义，迁移保持旧活动原状。

部分兼容 Responses 的 MaaS 网关会将自动 JSON Schema 参数拒绝为 `400001 / invalid_request_error`，错误说明为内部 MaaS 组件拒绝且 `param` 为空。这一明确拒绝允许一次移除自动 `text.format` 的兼容验证，保留全部其他请求字段、原模型和提示词；字段结构仍由提示词与本地校验约束。该处理仅作用于上述错误签名和程序自动生成的格式，普通 400、用户配置的格式、网络异常及服务端不确定错误不走此路径。

恢复运行会复用已收到的文本进行本地校验；显式“重试此步骤”才为已确认的校验失败创建新请求，保留此前每次原始返回，并把安全的字段错误加入重试提示。请求使用 JSON 输出约束，提示词的字段说明与校验 Schema 同源，用户已配置的输出格式保持优先。每次请求独立记录用量，已完成的简报、风格、其他步骤和原检查点继续复用；成功后停在选中步骤。工作区版本 17 保护本地文本回执语义，迁移不推断或改写旧的未知提交，旧记录没有保存的原文和字段错误不能补造。

媒体镜头卡片的“重新生成”进入现有候选流程，`shot.regenerate.source` 固定原运行、步骤和请求 UUID。新任务只包含所选镜头，使用原步骤的实际输入、冻结模型与 Skill、上游产物和参考素材；候选的应用基线单独记录当前镜头，沿用字段冲突保护与可撤销应用。源运行、其他镜头和上游产物保持原记录。来源任务使用处理器版本 4，旧处理器会拒绝执行；请求回执随运行持久保存，重复请求返回原任务，未完成任务通过原身份继续或停止。工作台继续展示原制作进度，单镜头后台任务单独提供活动身份。

完整多步骤制作成功后，运行上下文自动保存到项目；项目修订必须仍与启动快照相同，并在同一事务保存应用回执，恢复时不会重复应用。制作期间存在项目编辑时保留当前内容，记录冲突事件，步骤产物仍可查看。单步执行、显式局部范围、镜头候选、资料提取与批量导出保持各自的应用或输出契约。

重放检查只读取历史记录，不提交模型、工具或渲染操作。继续运行恢复旧快照；修改后重做创建关联的新运行。

“制作记录 → 查看步骤”读取冻结流程和原生 SQLite 检查点，区分待执行、已完成、条件分支未经过、历史暂停及历史未记录。完成活动的回执不等于编排检查点已经推进；产物先保存、检查点尚未推进时，详情保持这个差异。没有冻结流程的旧运行只展示已有活动和日志，不以当前项目流程补造历史。

步骤输入来自 `node-project` 中步骤实际开始时的上下文，包含上游已经生成的项目内容。新活动额外保存输入摘要和执行时的提示词；已完成或已提交的旧回执在恢复时不补造最终提示词。这是执行上下文记录，不代表 HTTP 请求的逐字副本。输入和产物按所选步骤读取，历史版本先分页加载元数据，再读取明确选择的版本。

查看与比较不会调用生成器。应用产物先进入项目编辑会话，沿用当前修订、冻结项目基线、角色和素材校验，产生可撤销编辑；生成后已有人工修改时保留原内容并拒绝覆盖。画面、旁白及视频使用所选步骤的实际输入与产物计算对应状态，不读取整次运行最后的 `run-project` 来替代较早步骤。素材在应用前流式核对大小与哈希，异步读取结束后再次核对项目修订和素材身份。

自动化调用 `node.apply` 可提供稳定 `applicationId`。相同标识及运行、节点、修订的重试返回第一次提交结果，回执与项目写入在同一事务中保存；标识复用于不同参数会拒绝。确认丢失后的重试不会覆盖第一次应用之后的人工编辑。

诊断由用户明确导出为本地 `.json.gz`，包含冻结快照、检查点摘要、步骤上下文／产物及捕获上界以内的全部活动和事件。导出按记录流式压缩，记录开始与完成时间；活动制作期间不声称它是跨所有表的原子快照。已知模型密钥、敏感字段、URL 凭据和签名参数会隐藏，媒体数据保留素材引用。失败只清理由这次导出创建的未完成文件。

本地取消信号必须传递到正在等待的操作及子进程。原生层负责清理附属进程；远端任务取消不成功时保留可查询编号及状态。

## 文件与数据库

产物先写入临时路径，经文件探测和校验后原子重命名。完成活动、资产版本和相关业务状态在同一应用事务中登记。检查点尚未推进时，恢复依照已提交的活动结果返回，不重做外部操作。

一次工作区只由一个执行进程负责数据库写入。同一项目同时只能有一份活动运行。数据库使用 WAL、外键检查和同步持久化；此保证属于本机实例范围。

## 验证场景

- 结果已保存、图检查点尚未推进时退出进程。
- 外部提交结果不明确时退出并重新继续。
- 已保存远端任务编号后中断轮询和下载。
- 历史暂停检查点重启后自动继续。
- 重新进入节点时复用完成结果。
- 重放过程中验证外部调用次数为零。
- 旧运行快照与新项目修订保持隔离。
- 文件缺失、损坏或只存在临时输出时不展示为完成。
- 双层子流程自动接续及跨重启恢复，固定版本备份恢复及真实参数化 ASR 应用。
- 镜头原生 pending write、已知远端任务、未知提交和待下载阶段实际 SIGKILL 后重启。

## 提示词实验与版本

`prompt.preview` 从当前项目修订、任务草稿和可选创作上下文构造独立快照，不取得模型密钥、不创建活动或费用记录、不提交生成。文本与媒体分别共用正式执行的提示词构建器；媒体参考和所选历史上游产物执行类型、项目归属与文件哈希校验，实际提交前再次核对冻结文件。上游只能来自同项目成功正式运行中已保存的祖先步骤，不补跑缺失步骤。

`promptSession.save` 校验预览摘要并按会话修订比较保存；每个修订独立保存输入快照。`promptTrial.start` 使用会话修订和请求 UUID，将运行、冻结快照及去重回执原子写入，再交给现有执行器。重复请求返回原运行，复用请求身份提交不同输入会拒绝。试运行的 `purpose` 为 `prompt-trial`，记录会话及其修订，仅执行一个节点；媒体与单镜头分镜使用既有候选机制。实验不能自动应用项目或通过父运行接续制作，正式阶段进度忽略实验。中断后由用户继续原运行；已提交但结果未知的请求保持待核对，恢复和重放不自动重提。

首版实验支持简报、风格、分镜、单镜头参考图及原生视频生成。工具型 Agent、资料整理、子流程、本地剪辑与导出继续使用各自入口。显式应用产物仍核对当前项目修订、角色与素材完整性，并沿用编辑历史和候选保护。

`promptLibrary.save` 为模板和快捷片段创建不可变版本；收藏、归档等元数据独立增加修订。任务保存提示词正文、`promptBindings` 和可选的 `promptTemplate` 版本引用，执行不依赖模板当前版本。变量只解析 `{{名称}}`，支持 JSON 字面值、受限项目和镜头字段，以及上游 JSON 字段；字段遍历复用现有绑定解析，拒绝原型路径与表达式。旧任务未声明绑定时保留原有提示词字面内容。子流程展开时映射绑定中的局部任务身份。

工作区迁移 13 防止旧客户端丢弃提示词契约。单项目格式 6 备份携带复制的任务正文及绑定，模板引用用于溯源；全局提示词库和实验历史属于工作区，不包含在单项目备份内。

## 作品分集与持久化生产队列

作品文档 `story-work` 保存默认风格、创作上下文、成片规格和统一制作设置。默认设置只复制到新分集；参考音频由每个项目独立选择。已有分集通过 `work.defaults.apply` 选择字段显式同步，批次先核对全部项目修订、角色和文字设定，再在事务中写入。系列模板仍然是视觉设置预设。

分集关联保存在项目 `episode`，包含作品 ID、集数、原始文案和继承默认设置的修订；项目标题作为分集标题。原始文案独立于生成后的简报。批量建项使用请求 UUID 和输入摘要记录持久回执，项目与回执在同一事务中保存。集数由数据库唯一索引保护，回收站项目也保留编号；移出作品后保留 `episodeSource` 来源。

队列按请求中的项目顺序保存 `production-queue` 和独立的 `production-queue-item` 文档。入队记录项目基线修订及请求身份，同项目的活动项在所有队列间唯一；重复请求或另一个请求中的活动项目复用已有项。新队列默认暂停，用户显式开始后按顺序派发。单个工作区的队列协调器至多执行一个排队项，普通运行和镜头内部调度继续由既有执行器管理。

开始每项之前再次检查项目修订、归属和归档状态；不一致时标记需要处理，用户核对并刷新后恢复为暂停状态。普通制作入口、实验和批量导出遵守排队预留，避免绕过活动项创建重复制作。队列通过相同的 `run.start` 准备逻辑构建完整冻结快照，排队项认领、运行及其快照在一个 SQLite 事务中关联；`RunRecord` 保存 `productionQueueId` 与 `productionQueueItemId`，唯一索引防止一项创建多个运行。

成功后派发下一项。失败、未知外部提交、取消当前运行、或制作期间项目修改造成自动应用冲突时，停止该队列后续派发并保留已有产物。暂停只关闭后续派发，当前运行继续；取消后续排队项同样保留正在运行的分集，停止当前制作使用单独操作。失败项可继续原运行或跳过并保留产物；有运行身份的项不能通过刷新重建任务。继续制作记录中的队列运行也会回到队列的所有权校验。

重启时先读取关联运行状态：已完成的运行补齐队列投影；中断的原运行标记需要处理，用户继续同一运行和检查点。已提交但结果未知的外部活动依旧依赖原回执核对，不自动重提或切换模型。队列持久化保证面向一个工作区 Runtime，不提供多进程租约或分布式所有权保证。

迁移 14 增加分集、活动项目、单个执行项和排队项运行的唯一约束，并升级项目摘要投影；旧项目与运行快照保持原内容。格式 7 单项目备份携带分集来源，导入创建独立项目，不自动加入原作品；重新加入作品需校验编号。整部作品及队列的跨工作区打包迁移属于后续范围。
